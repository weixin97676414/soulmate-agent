## 一、已拍板的四项决策（2026-10-22 用户确认）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 代码组织 | **同一份代码跨平台化**：在原仓库 `Soulmate Agent 开源代码` 里用 `process.platform` / `sys.platform` 分支，不复制独立 mac 副本 |
| 2 | 桌面能力深度 | **首版优雅降级**：电脑操作 / 剪贴板 / 音量亮度锁屏在 mac 上标注「仅 Windows 支持」，不报错、不影响其余功能，后续再补 osascript 等价物 |
| 3 | 更新策略 | **整包替换**：mac 检测到新版本下 dmg/zip 整包替换（文件级增量会破坏已签名 .app），起步不用 Sparkle |
| 4 | 构建环境 | **GitHub Actions mac runner**（`macos-latest`），本地只做代码 + 配置 + 脚本逻辑验证 |

**补充**：代码签名 / Apple 公证需要 **Apple Developer ID + 开发者账号**（外部依赖，由用户提供）。阶段 1–5 不依赖它；到阶段 6 构建/签名时才需要，未就绪前可先出未签名 `.app` 供内测。

## 四、关键约束（不要忘）

1. **当前开发机是 Windows**，无法本地构建/签名/公证 mac 产物——阶段 6、7 必须在 mac 环境（GitHub Actions）跑。
2. **不改 Windows 现有行为**：所有平台改动用「只增 darwin 分支、不动 win32 分支」原则，Windows 版 pytest/vitest/verify 全绿是回归基线。
3. **mac 更新只能整包**：已签名 `.app` 内文件被替换即失效签名，不做文件级增量。
4. 签名证书是外部依赖，阻塞点只影响阶段 6，不阻塞阶段 1–5。
