# macOS 签名与公证 · 说明

> 本文件记录 mac 版要上线所需的签名/公证准备。真正的构建在 GitHub Actions `macos-latest` 上跑，
> 签名/公证需要下面这些 secrets，缺了就先出**未签名包**供内测。

## 一、需要准备的三样（Apple Developer）

| 项 | 用途 | GitHub secret 名 |
|---|---|---|
| Developer ID Application 证书（.p12 + 密码） | 给 `.app` 签名 | `MAC_CSC_LINK`（base64 的 .p12）、`MAC_CSC_KEY_PASSWORD` |
| Apple ID + 专用密码（app-specific password） | 公证（notarize） | `APPLE_ID`、`APPLE_APP_SPECIFIC_PASSWORD` |
| Team ID（10 位） | 公证的团队标识 | `APPLE_TEAM_ID` |

- 证书：`developer.apple.com` → Certificates, Identifiers & Profiles → 新建 **Developer ID Application** 证书，导出成 `.p12`（含私钥）。
- 专用密码：`appleid.apple.com` → 登录与安全 → App 专用密码 → 生成一个。
- Team ID：`developer.apple.com` 右上角会员信息里那串 10 位字符。

## 二、secrets 怎么配

在 GitHub 仓库 → Settings → Secrets and variables → Actions → New repository secret，逐个建：
`MAC_CSC_LINK`、`MAC_CSC_KEY_PASSWORD`、`APPLE_ID`、`APPLE_APP_SPECIFIC_PASSWORD`、`APPLE_TEAM_ID`。

其中 `MAC_CSC_LINK` 放 `.p12` 的 **base64**：
```bash
base64 -i devid_application.p12 | pbcopy   # macOS 上执行，然后粘贴到 secret
```

## 三、entitlements 与权限

`desktop/build/entitlements.mac.plist` 已经写好了麦克风（`com.apple.security.device.audio-input`）、
摄像头、JIT、用户文件读写、下载目录读写。语音要用的麦克风权限同时需要
`Info.plist` 里的 `NSMicrophoneUsageDescription` —— 这个已在 `desktop/package.json` 的
`build.mac.extendInfo` 里配好，构建时自动写入。

## 四、首版流程（未就绪证书前）

1. 不配 secrets，直接跑 workflow → 得到**未签名**的 `.dmg`/`.zip`。
2. 内测机安装后，首次打开被 Gatekeeper 拦时执行：
   ```bash
   xattr -cr "/Applications/Soulmate Agent.app"
   ```
   或在「系统设置 → 隐私与安全性」里点「仍要打开」。
3. 证书就绪后，配好 secrets 重跑 → 得到签名 + 公证的正式包，可正常分发、自动更新。

## 五、自动更新与签名

mac 版更新是**整包替换**（`updater.ts` 里按平台走 mac 整包地址），不做文件级增量
（已签名 `.app` 内文件被替换即失效签名）。所以每次发布都要重新签名 + 公证整个包。
