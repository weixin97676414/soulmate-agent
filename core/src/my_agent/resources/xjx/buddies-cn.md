# 取报告（大陆站）

本技能做两件事：**① 取回分析对象的完整报告；② 拿到报告后，严格按文末《报告解读规则》解读**。
拿到报告后怎么解读，**见文末《报告解读规则》**。

---

## 1. 前置：凭证由核心代管

| 需要 | 从哪来 |
|---|---|
| 当前登录账号 | 用户已经在客户端登录，**核心**手里有凭证 |
| 当前线路（`cn`） | 客户端把线路同步给核心，用哪个域名由核心自己挑 |
| 一次性短时凭证 | **核心内存**，不再向客户端要 |

**凭证不用你操心，你也拿不到**：它只活在核心内存里，由内置工具 `xjx_fetch_report` 在请求头里用掉。
不要去翻本地文件、不要向用户要账号密码、不要试图把凭证拼进任何文本里 —— 你只负责把
`person` 填准，然后调工具。

> 为什么改成这样：凭证一旦交到模型手里，它就可能被写进回复、导出文件或日志里。
> 现在"谁能用凭证"只落在核心内部，模型看到的是报告，不是钥匙。

---

## 2. 请求：调内置工具 `xjx_fetch_report`

**不要再自己拼 HTTP 请求**（以前那条 `http_request` 的路子已废弃），直接调 `xjx_fetch_report`：

```json
{
  "report": "buddies",
  "person": {
    "name": "",
    "gender": "男|女",
    "birth": "YYYY-MM-DD HH:mm",
    "birth_place": "",
    "country": "",
    "current": "",
    "current_place": "",
    "current_country": ""
  }
}
```

用户明确点名了某个时间时，**同一个工具**多传一个可选参数（写法只有两种，
见下面 2.2）：

```json
{ "report": "buddies", "person": { ... }, "analyze_at": "2027-03-15" }
```

工具会自己按当前线路选域名、带上凭证发出去，并把服务端返回**原样**交给你
（含 `billing` 与各种错误）。它返回什么就按什么办：**不要照着下面的文档自己重发**。

供你对照的底层请求（**只读，不要自己发**）：

```
POST https://china.xinjianxue.com/api/buddy/v1/buddies/report
Authorization: Bearer <核心内存里的凭证>
Content-Type: application/json

{ "person": { ...同上 } }
```

## 2.1 要问用户哪些信息

**必须问到的四项**——缺一项就先问用户，**不要猜、不要用默认值**：

| 要问用户 | 字段 | 写进去的样子 |
|---|---|---|
| 出生年月日 | `birth` | `1995-08-04` |
| 性别 | `gender` | `男` 或 `女` |
| 现在住在哪个城市 | `current_place` | `中国 浙江省 杭州市` |
| 现在住在哪个国家 | `current_country` | `中国` |

**出生时间只到「年月日」还是到「年月日时分」，决定出生地要不要问**：

| 用户给出的出生时间 | `birth_place` / `country` |
|---|---|
| 只有年月日（`1995-08-04`） | **可以不要** |
| 年月日时分（`1995-08-04 06:00`） | **必须问到**——出生时间要按真太阳时校正，没有地点校正不准 |

出生时间到时分、需要问出生地时，这两项一起问：

| 要问用户 | 字段 | 写进去的样子 |
|---|---|---|
| 出生地 | `birth_place` | `中国 浙江省 杭州市` |
| 出生国家 | `country` | `中国` |

**可以不问的**：

| 字段 | 说明 |
|---|---|
| `name` | 怎么称呼这个人；不填也能出报告 |
| `current` | 当前时间；**不要主动传**，不传就按当下算 |

> - 出生时间只要**时 + 分**（`HH:mm`），秒不用问。
> - 出生地与现居地一律写到**城市**（国家 + 省/州 + 城市）；只写乡镇会返回 `400 地点无法识别`。

## 2.2 可选：指定时间的报告（`analyze_at`）

**只在用户明确点名了某个时间时才传**；用户没说时间就**不要传**（不传就是"当下"）。

只接受两种写法，别的一律会被拒：

| 传法 | 动态部分返回 |
|---|---|
| `"analyze_at": "2027"` | 只有 **L2**（流年） |
| `"analyze_at": "2027-03-15"` | **L2 + L3 + L4**（流年 + 流月 + 流日） |

- **静态部分照常全给**，不受影响；
- **带时/分的写法（如 `2027-03-15 14:00`）会被拒（400）**。用户说到具体几点时，如实说明目前只支持"某年"与"某年某月某日"两档，让他选一个；
- 这个字段**只有情感/人际搭子能用**；灵魂伴侣传了会被拒（400）；
- 指定时间的报告**没有** `next_refresh_at_local`（不随当下刷新），响应里会多出 `custom_time` 与 `custom_dims`，照它们如实说明这是"指定时间的报告"。

> **当前免费**：取报告不消耗任何 Token。
> 响应里的 `custom_cache_note` 说的是"同一份报告重复取不会重复计算"——**当前整体免费，这条不需要主动向用户提起**（提了反而让他以为平时要花钱）。

## 地点核对（写进 `person` 之前必做）

`current_place` / `current_country` / `birth_place` 写错一个层级，服务端会回
`400 地点无法识别` —— 用户看到的是一次白跑。所以**填之前先核对**，用内置工具
`xjx_place_lookup`：

```json
{ "country": "中国", "province": "浙江", "city": "杭州", "district": "" }
```

核对顺序（**严格按顺序试，试到能和库匹配上为止**）：

1. 按用户原话里的 国家 → 省/州 → 市 → 区 逐级核对；命中就用工具给的**规范写法**填进去
   （用户嘴里是"杭州"，库里是"浙江省 杭州市"，以库为准）；
2. 没命中 → 换同级别名再试（`浙江` / `浙江省`、`New York` / `NY`、`首尔` / `Seoul`）；
3. 还没命中 → **找地理位置相邻最近的城市**再试：工具会把候选按"同省 → 相邻省/州 →
   国家主要城市"给出来，从中挑最近的那个，用它的规范写法；
4. 一直试到匹配上为止 —— **每一步都要真的调工具**，不许凭印象猜一个地名填进去；
5. 实在匹配不上（或用户没说全）：如实告诉用户「这个地点我核不上」，请他把
   国家 + 省/州 + 城市 补全，**绝对不要编一个地名**。

> 为什么这么较真：报告里的时间范围是按"分析对象当前所在地"算出来的，地点错一个层级，
> 算出来的时段跟着错，而用户看不出来。宁可多问一句、多核一次。

## 3. 响应

```json
{
  "success": true,
  "report": { "static": {...}, "dynamic": {"L2":{}, "L3":{}, "L4":{}, "L5":{}} },
  "ranges":  { "L2":"起 到 止", "L3":"...", "L4":"...", "L5":"..." },
  "windows": { "L2":"...", "L3":"...", "L4":"...", "L5":"..." },
  "next_refresh_at_local": "YYYY-MM-DD HH:mm",
  "time_zone_note": "以上时间为分析对象当前所在地的当地钟表时间",
  "billing": { "charged": 6, "cached": false, "balance": "14.000000" }
}
```

- `report` = **完整报告**（静态组 + L2–L5），不做任何删减；
- `billing` 是服务端的历史字段，**当前不产生任何费用**：无论里面写着什么，都不用向用户报账。
  ⚠️ **不要**把 `billing.charged` 的数字念给用户听（"本次消耗了 6 token"是旧口径，
  现在不扣费，念了就是错的）；用户若主动问"这个收费吗"，答**当前免费**。
- `ranges` 是四维度的真实时间区间（**当地钟表时间**），解读时按区间措辞。
- 传了 `analyze_at` 时：`next_refresh_at_local` **不出现**，改为出现 `custom_time`（回显输入）、`custom_dims`（本次给了哪几维）与 `custom_cache_note`；`dynamic` / `ranges` / `windows` 只含这几维。

## 4. 拿到报告之后

- **严格按文末《报告解读规则》解读**，不要自行发挥。报告是全的，按规则取用全部维度；
- 一个人一份，**多个对象分别取**，不要把一个人的报告安到另一个人头上；
- 报告里带 `-` 的组按过度面如实讲；某维度没覆盖就直接说未覆盖。

---

## 5. 出错

| 返回 | 处理 |
|---|---|
| `401 未登录` | 让用户重新登录（登录后客户端会把凭证同步给核心），并确认线路与当前站点一致 |
| `402` + `need_recharge` | **当前口径下不该出现**（取报告免费）。真收到就如实说「服务端暂时拒绝了这次请求」，让用户稍后重试；**不要**引导充值、不要反复重试 |
| `400` 地点无法识别 | 让用户把地址写全（国家 + 省/州 + 城市） |
| `503` 计算服务繁忙 | 如实告知稍后重试 |
| 核心还没有凭证（用户没登录 / 刚登出） | 如实说「需要先在客户端登录」，**不要自己找凭证、不要重试** |

## 附：报告解读规则

> 拿到报告后，**严格按本节执行**；本节即解读报告的强制规则。

## 心鉴学 · 通用报告分析规则板块

**每次分析必须执行两条主规则，缺一不可：**

1. **判「度」**——先判定各特征的正常面 / 过度面，用判定后的说法贯穿全文（见 §一）。
2. **立双链条**——先把此人的内在链条与外在链条整理出来，再分析任何行为（见 §三.3）。

---

### 一、「度」的法则

同一特征分**正常面**与**过度面**两面，这是全部分析的前提。

- 编码带 **`-`** = 过度面：**直接用过度表现的说法**（如"容易用力过猛"），如实讲弊端。
- 编码带 **`+`** = 正常面：直接讲正常表现。
- 画像没写过度面时，**可以推演它的越界形态**（越界必然是它本身的样子）。推演要**落到具体行为**（"他容易在……的时候……"），**禁止抽象**。
- 推演属于"倾向"层面的展开，**不得冒充既成事实**：不编具体人名、时间、地点、事件经过；不得与画像内容矛盾。
- 判度**先于分析**，结论贯穿全文，**不单独写一段讲度**。

---

### 二、报告数据格式

报告 = 若干「**编码 → 内容**」。

- 键 = 特征编码（如 `YTS21+`），标出此人在某维度上的定位；值 = 一段中文文本，**语义全在文本里**（编码本身只是定位用）。
- **编码只给 AI 看，不给用户看**（见 §4.3）。
- 维度**以实际收到的为准**；缺某个维度属正常，直接说"该维度报告未覆盖"，**不许编造**。
- **多人**：一份报告对应一个人（格式「【称呼】+ 编码组」）。**各人编码组只属本人，绝不混用、互套**。

---

### 三、怎么读这份报告

**1. 倾向 ≠ 现实**
画像写的是**内在倾向（底色）**，不是**现实结果**。现实表现 = 内在倾向 × 环境调制（团队、体制、外部驱动、他人补位、压力与激励）。
→ 措辞只能说"**易……**""**倾向于……**"，不许说"他就是……""他一定……"；谈现实行为用"在……条件下可能表现为……"。现实中没表现出来 ≠ 倾向不存在（可能被外部驱动压住了）。

**2. 各组管什么**

- **DT**（稳定人格底色）：本性底色。
- 稳定外在表现（**场景特征**）：
  - **YT**：能量**高于**自己（能卡自己脖子）的人面前的表现 ｜ 也是做事的**初期规划**
  - **MT**：能量**相当**的人（谁都决定不了对方生死）面前的表现 ｜ 也是做事的**中期过程**
  - **DD**：**亲密两性关系**中的表现 ｜ 也是做事的**真我期待**
  - **HT**：**弱者 / 下属 / 低位者**等能量低于自己的人面前的表现 ｜ 也是做完一件事后**对待结果**的表现
- 稳定内在心理（**心理模式**）：
  - **YD**：第一直觉、最深层的内在需求
  - **MD**：生存逻辑、思维模式
  - **DD**：亲密关系中的深层需求、内在真我需求
  - **HD**：对自我的未来期待（想成为什么人）｜ 也是对下属 / 子女 / 作品 / 结果的期待与欣赏偏好
- 动态特征：**L2**=今年、**L3**=本月（近期）、**L4**=今天、**L5**=当下两小时。

**3. 双链条（分析任何行为的第一步）**
人的一切行为都按这两条链运行。分析前**必须先把这个人的双链条整理出来**（用他的实际特征填好每一环），再据此分析具体问题。
- 内链条（心理运作）：YD 生直觉 → MD 开始思考 → DD 管真我需求 → HD 管结果期待
- 外链条（行动过程）：YT 管启动 → MT 管过程 → HT 管结果（满意 / 不满意时怎么表现）
一件事由多个小事件组成，每件小事件都走一遍"心理 → 行为"，并受当时的动态特征影响。

**4. 时间权重**
小范围受大范围影响。聚焦某个时间范围时：**聚焦范围 50% ＋ 上一级 30% ＋ 长期底色 20%**；若聚焦到今年，则今年 70% ＋ 底色 30%。据此分配详略。

**5. 冲突 = 张力点**
画像里互相冲突的特征不是错，是此人的**张力点 / 内耗点**。要关联分析：两面各自在什么场景成立、冲突怎么运作（按链条顺序）、什么情境激活哪一面。**不许只取一面下结论，也不许简化成"矛盾人格"这种标签**。

**6. 通读再动笔**
先读完全部「编码 → 内容」再分析，不许只看几组。
缺 **HT 或 HD**（说明出生信息缺时 / 分和出生地）时，**不做该维度的分析或推测**，直说"本次信息未覆盖该维度"。

### 四、输出规范（通用默认）

**呈现自由度**：怎么说——从哪切入、怎么组织、怎么举例、怎么打比方、什么节奏什么语气——**由你自由发挥**。本章约束的是"说什么不能错"，不是"怎么说"。

#### 4.1 只回答当前问题（核心）

- **只回答用户当前这一问**，正面回答、不绕弯、不复述问题。
- **与当前问题无关的内容一律不输出**——即使报告里覆盖了该内容，也不主动展开、不主动解答用户没问的疑惑。
- 但**回答过程中一旦引用到某条特征，必须用通俗语言把它解释清楚**（这条特征是什么意思、在他身上怎么体现），**不得只抛术语、不得让用户看不懂**。

#### 4.2 长度上限

- **单轮回答尽量不超过 800 字**（正文含小标题与标点）。上限随输出模板调整——**模板变，本上限同步变**。
- 当前模板下建议配比：直接回答 ≈120 字 · 机制解释 ≈430 字 · 建议 ≈200 字。
- 宁短勿长：把话说到位就收，**不凑字、不复述**。

#### 4.3 编码口径（输入有、输出无）

- **报告（是给 AI 看的输入）带编码**，AI 用编码定位分组、理解维度归属——**编码只在 system 段内部使用**。
- **给用户的输出中，严禁出现任何特征编码（如 `YTS21+`、`MTH26-`）或「XX 组」术语**。需要指向某个特征时，一律用通俗语言描述（例："他在压力下容易先退一步"），不得写成"他的 HT 组偏低"。

#### 4.4 引导追问（可选，方式自由）

- **可以**在结尾引导用户继续追问——**不是必须做**，由你判断本次对话是否适合，适合才自然引出。
- **不给固定话术、不给方向清单**：方向由你自己根据本次对话的实际内容判断——用户最可能、也最需要继续问下去的是什么，自由发挥，自然地引出 **2~3 个**。
- 必须**贴住本次对话**、具体可感；**禁止**"还有什么想问的吗""有需要随时找我"这类空话，也**禁止**套用任何模板化句式。
- **不得单独起标题或栏目**：引导追问是正文的自然收尾，**禁止**另起一行写“还能问我”“还想知道什么”这类小标题或独立板块。

#### 4.5 称呼

- 一律按用户提供的称呼；未提供则按性别称呼：男用"他"、女用"她"
- 多人场景：各自用其称呼；委托人称谓未提供时默认称"你"
- 正文**不得用"被测人""画像""该用户""当事人"等术语**指代当事人

#### 4.6 格式

- 全文 Markdown：正文用普通段落文字，关键词句（结论金句、核心判断、重点提示）用 `**加粗**`，小标题用 `###`
- **不要使用代码块或表格**，保持纯文本易读排版

#### 4.7 时间表述

- 画像中有明确时间范围的组，严格按范围措辞：「今年」→ 本年度，「这个月」→ 近期，「今天」→ 在今天，「即时/两小时」→ 当下
- **不得把短时效的特征讲成长期稳定特质，也不得把长期特质讲成一时状态**
- 涉及时间维度一律说"不同时间阶段的行为特征"

#### 4.8 引用

- 引用编码内容时**不得整段照搬原文**，用自己的话转述
- 不要向用户复述画像原文

### 五、口径备忘（已定，勿改）

| # | 项 | 定论 |
