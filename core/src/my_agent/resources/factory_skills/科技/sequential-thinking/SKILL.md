# 功能：序列思考与任务分解

基于 MCP Sequential Thinking Server 设计。

## 适用场景
分解复杂问题；需要修订的规划与设计；初始不清楚全貌的问题；需要多步骤保持上下文的任务；需要过滤无关信息的情况；需要对比多个方案。

## 思考流程
```
问题定义 → 信息收集 → 问题分解 → 多维分析 →
建立连接 → 生成方案 → 评估选择 → 实施反馈
```

## 参数（输入）
| 参数 | 说明 | 示例 |
|---|---|---|
| `thought` | 当前思考内容 | "首先分析问题边界…" |
| `thoughtNumber` | 当前步骤编号 | 1 |
| `totalThoughts` | 预估总步骤数 | 8 |
| `nextThoughtNeeded` | 是否需要下一步 | true |
| `isRevision` | 是否修订之前思考 | false |
| `revisesThought` | 修订的步骤编号 | 3 |
| `branchFromThought` | 分支起点 | 5 |
| `branchId` | 分支标识 | "方案A" |
| `needsMoreThoughts` | 需要更多步骤 | false |

## 步骤
1. **问题定义**：明确任务目标与边界，识别关键约束。
2. **信息收集**：检索相关记忆、搜索必要信息。
3. **问题分解**：拆子任务、定优先级。
4. **多维分析**：技术（可行性/复杂度）、用户（体验/偏好）、时间（紧急度/工作量）。
5. **建立连接**：关联已有知识、识别依赖。
6. **生成方案**：提出多个候选，考虑分支可能。
7. **评估选择**：对比优劣，选最优路径。
8. **实施反馈**：执行并监控，根据反馈调整。

## 分支与修订
- 分支（当前路径可能非最优）：`branchFromThought: 5, branchId: "方案B"`，必要时增加 `totalThoughts`。
- 修订（发现之前思考有误）：`isRevision: true, revisesThought: 4`。

## 输出
思考记录可输出为 Markdown 存到 `memory/thinking-YYYY-MM-DD.md`，结构：`# 思考记录：<主题>` + 各步骤小节 + 「评估选择」给推荐 + 「实施反馈」给结果。

示例输出：
```json
{ "thoughtNumber": 1, "totalThoughts": 8,
  "thought": "首先分析问题边界：用户需要一个金融数据看板",
  "nextThoughtNeeded": true, "branches": [] }
```

## 与 OpenClaw 集成
- 自动触发条件：任务涉及多个步骤、复杂度超阈值、用户要求「思考一下」、需对比多个方案。
- 也可在 System Prompt 中内嵌八步「思考模式」约束（见上）。

## 注意事项
- 步骤数应随理解深入动态调整，不要硬凑固定步数。
- 修订要显式标注（`isRevision`），避免自相矛盾的结论并存。
- 分支探索要收敛回主路径或明确选择理由。

## 可复用示例
> 「把金融数据看板部署到公网」：步骤 1 定义任务 → 步骤 2 收集（本地可跑、需公网 URL/免费方案）→ 步骤 3 拆解（选平台/修依赖/上传/测试）→ 步骤 4 多维分析 → 步骤 7 评估选择（Streamlit Cloud 免费自动部署，推荐）→ 步骤 8 实施反馈（部署成功，URL 记录）。
