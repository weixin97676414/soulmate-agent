# 商业智能（BI：KPI、指标树、仪表盘、决策节奏）


## 适用场景

- 搭建或改进企业 BI 系统：KPI 定义、指标架构、仪表盘规划、高管汇报、决策复盘闭环。
- 面向运营、创始人、产品负责人、财务负责人与分析师，回答「什么变了、为什么变、下一步做什么」。

## 边界

本技能只做企业 KPI 体系：指标树、KPI 契约、仪表盘规范、决策简报与运营节奏。增长实验（AARRR）与漏斗归因诊断不在本技能范围。

## 核心规则（步骤）

1. **从决策问题出发，而不是图表**：每个 BI 请求必须从一个决策问题和一个负责人开始；没有决策负责人时，输出就是汇报噪音，先重构再建指标。
2. **先建指标树，再设计仪表盘**：把每个业务目标映射到驱动因素，再映射到可度量 KPI；不要先做仪表盘——没有指标树的仪表盘会产出一堆互不相连、叙述矛盾的图表。
3. **强制 KPI 契约**：每个 KPI 需要书面契约：定义、公式、粒度、来源、刷新频率、负责人、有效解读窗口。公式版本或来源逻辑变更且未标注时，**绝不跨期比较 KPI 数值**。
4. **区分领先与滞后指标**：每个滞后 KPI 至少配一个领先指标；只追滞后结果会导致干预太晚。
5. **用决策格式做简报**：每条洞察必须含「什么变了 / 为什么变 / 置信度 / 建议动作 / 动作负责人与截止日」；缺少动作负责人的 BI 摘要不完整。
6. **跨团队统一仪表盘规范**：统一的指标命名、时间窗、分群逻辑、颜色语义与下钻路径；规范不一致会导致跨团队比较无效。
7. **固定运营节奏**：定义日/周/月/季的 BI 仪式，明确参与者与升级触发条件；没有固定节奏，KPI 复盘会变成被动反应，决策质量下滑。

## 输入 / 输出

- **输入**：决策问题与负责人；业务目标；现有指标/数据源；复盘周期。
- **输出**：指标树、KPI 契约、仪表盘规范、决策简报（含建议动作、负责人、截止日）、运营节奏文档；均落在 `~/business-intelligence/` 下。

## 注意事项（BI 陷阱）

- 先上可视化工具、后补 KPI 契约 → 昂贵仪表盘 + 弱决策。
- 每个目标追踪过多 KPI → 团队失焦，看不到真正的驱动因素。
- 把预测假设与实际值混在一个数字里 → 高管产生虚假确定性。
- 改公式不留版本说明 → 历史趋势比较失效。
- 只报变动、不做归因 → 团队无法找到正确干预点。
- 发 BI 更新但不写动作负责人 → 洞察无法转化为执行。
