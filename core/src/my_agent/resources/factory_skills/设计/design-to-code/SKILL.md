# 设计稿转代码（还原设计图）
## 适用场景

- 把 Figma / Sketch / 设计图截图 / 标注稿高保真还原为前端代码
- 用户说「还原设计图」「按设计稿实现」「切图」「设计转代码」
- 提供 Figma/Sketch 链接、设计图截图或标注，要求实现某页面/组件

## 步骤

1. **先确认用户给了什么**：Figma 链接（问有无访问权限，无权限则让用户截图/导出标注）；设计图截图（直接分析）；只有描述（先问有无设计稿，无则按常见 UI 规范实现并说明可能有出入）；设计图 + 现有代码（先读现有代码，摸清技术栈与已有组件）。
2. **分析设计稿，按顺序提取**：
   - 布局结构：几列、Flex 还是 Grid、区块固定/弹性、响应式断点
   - 间距尺寸（px 级）：容器 padding、元素 gap/margin、组件宽高
   - 字体：字号/字重/行高/字间距/颜色（含透明度）
   - 颜色：背景/文字/边框/阴影，能否映射到现有 design token 或 Tailwind 色
   - 交互状态：hover/focus/active/disabled（未标注的按项目现有规范，不自己发明）
3. **按固定顺序写代码**：① HTML 语义骨架 → ② 布局（Flex/Grid 对齐间距）→ ③ 字体排版 → ④ 视觉装饰（背景/边框/圆角/阴影）→ ⑤ 交互状态 → ⑥ 响应式 → ⑦ 动效（设计稿有说明才加）。
4. **处理歧义**（见注意事项）。
5. **提交前做还原度自检**（见下）。

## 歧义处理规则

| 情况 | 做法 |
|------|------|
| 设计稿颜色/字号在项目 token 里没有 | 先问「这个 `#3B82F6` 是否对应 `blue-500`？」；确认没有对应 token 再用 CSS 变量命名（`--color-brand-primary`），不写魔法值 |
| 标注不清晰、看不出数值 | 说明哪里看不清 + 给合理推测值让用户确认（"这里间距看起来是 16px，对吗？"） |
| 有动效但无说明 | 不发明动效，问持续时间和缓动函数 |
| 实现后与设计稿有出入 | 主动说明差异与原因（如"项目未引入 Inter，用了系统字体代替"），不假装没有 |

## 输入输出

- **输入**：Figma/Sketch 链接、设计图截图、标注、现有代码、技术栈。
- **输出**：与设计一致的组件/页面代码；可复用部分拆成命名清晰的组件；语义化 HTML + 合理 ARIA。

## 注意事项

- 使用项目现有技术栈（Next.js / Tailwind / SCSS / 组件库），不要另起炉灶。
- 设计稿里的未标注交互状态不要自行发明。
- 提交前自检清单：
  - [ ] 关键尺寸与设计稿一致（容忍 1–2px 差异）
  - [ ] 字体、颜色与设计一致
  - [ ] 主要断点下布局正常、无错位
  - [ ] 可交互元素有明确状态反馈（hover/focus/disabled）
  - [ ] 语义化 HTML（按钮 `<button>`、链接 `<a>`，不用 div 顶替）
  - [ ] 图片有 `alt`
- 输出时注明与设计稿差异及原因（兼容性、可访问性等）。

## 可复用示例

**常用对照表：**

| 设计稿 | 实现方式 |
|--------|----------|
| 8px 栅格 | 间距用 8 的倍数（8/16/24/32） |
| 字体层级 | 对应 heading/body/caption 语义类或 design token |
| 模糊/毛玻璃 | `backdrop-filter` + 半透明背景 |
| 多行截断 | `line-clamp` 或 `-webkit-line-clamp` |
| 安全区域 | padding 配合 `env(safe-area-inset-*)` |
