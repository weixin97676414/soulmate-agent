# 简历与面试三方评估优化

本技能从**求职者视角**出发，帮候选人优化简历、准备面试；与招聘方（HR/用人方）的筛选与打分工具方向相反——本技能不做招聘侧的简历筛选与录用决策，也不另立「简历×JD」打分口径。

## 适用场景

- 发送简历或目标岗位 JD，需要：JD 岗位逐条拆解与深度解读、三方视角评估（HR + 业务 BP + 第三方）、行业竞争力分析、模拟面试问题、可执行强化规划。

## 步骤

1. **安全红线检查**（`assets/resume-optimizer/safety.md`）：脱敏处理（姓名/电话/邮箱/地址/照片→XXX）；合规检查，禁止歧视性/违规内容。
2. **用户意图识别**（`assets/resume-optimizer/research.md`）：判断是简历/岗位/两者/修改需求，选择生成模式。
3. **简历与岗位基础分析**：基础信息、人岗匹配、履历逻辑、软实力；岗位分类（技术/非技术/通用）。
4. **JD 岗位拆解与深度解读**（`assets/resume-optimizer/jd-decoder.md`）：对岗位每条信息逐项拆解，输出"字面意思"+"深度解读"；维度：岗位名称/薪资范围/工作经验要求/岗位职责/任职资格/福利描述。
5. **三方评估**（`assets/resume-optimizer/evaluation.md`）：HR 视角、业务 BP 视角、第三方视角。
6. **行业竞争力分析**：供需趋势与竞争热度、核心技能基准对比、薪酬参考区间（分城市等级）；引用数据须标注来源。
7. **模拟面试问题**（`assets/resume-optimizer/output-rules.md`）：至少 3 个问题，每个含 思路转化/正确示例/错误示例/强化方向。
8. **强化规划**：弱点项 + 学习动作 + 时间周期 + 产出物。
9. **强制输出检查与输出**：自检清单逐项核对、格式规范检查。

## 输出规范

- **唯一生成文件：简历**——纯文本，无 Markdown/HTML 标签，不用表格或空格对齐分栏，每行顶格、空行分隔；命名 `[目标岗位]+XXX（姓名）.doc`（未给姓名→`XXX（姓名待补充）`，未给岗位→`待定岗位`）。
- 其余全部内容（JD 拆解/三方评估/行业分析/面试题/强化规划）：**以对话形式直接在 Chat 输出**，不生成 .md/.txt/.doc 等独立文件；纯文本、手机端可读。
- 简历转 PDF：Ctrl+P → 打印机选 "Microsoft Print to PDF"。

## 输入输出

- 输入：简历和/或目标岗位 JD。
- 输出：简历文件（如需）+ 对话内的评估、分析、面试题与规划。

## 注意事项

- 全程脱敏，不存储原始数据，不做人脸识别。
- 禁止生成任何歧视性内容；所有引用数据标注来源。
- 遵守《个人信息保护法》《民法典》《知识产权法》等法规；本技能为工具性质，不具法律主体资格、不作承诺或保证。
- 详细规则见 `assets/resume-optimizer/`。

## 可复用示例

用户：附上简历 + JD "负责 XX 产品基础体验优化"。
- **字面意思**：对产品功能进行体验优化，通过评估、数据分析和用户反馈定位改进点并实施优化。
- **深度解读**：该岗位以日常体验优化和迭代为主，工作重心在持续改进，涉及较多评估与分析，需要耐心与细致；面试可重点准备过往体验优化项目与评估方法案例。
- 随后输出三方评估、行业竞争力分析、≥3 个模拟面试题与强化规划，全部在对话内完成。
