# 临床诊断决策支持

## 适用场景

面向执业医师的临床诊断推理辅助。当用户提供病历文本、化验结果、体格检查发现，并需要以下任一项时使用：

- 疑似诊断推导（无当前诊断）
- 鉴别诊断（已有当前诊断）
- 误诊 / 漏诊风险评估
- 缺失信息识别（"还缺什么检查"）

触发词：分析病历、诊断分析、鉴别诊断、疑似诊断、漏诊风险、缺失信息、diagnostic analysis、differential diagnosis。

不适用：治疗方案推荐、病历文书撰写、面向患者的用药解释。本技能**只输出诊断结论本身**。

## 步骤

1. **输入解析**：接收非结构化病历文本或结构化 JSON；抽取主诉、现病史、既往史、个人史、家族史、体格检查、辅助检查。判断是否含"当前诊断"（`current_diagnosis`）。
2. **急症提示检测（P0，命中即独占输出）**：比对急症触发规则（关键词 / 阈值）。命中任一条 → 报告**只输出「急症提示」段**，不再输出疑似诊断 / 鉴别 / 误诊漏诊 / 缺失信息。命中 1–3 条逐条列出；> 3 条输出前 3 条 + "多重危急表现，需立即多学科评估"。卡片仅含"疾病类别 + 时间窗 + 3 条立即动作 + 必须通知团队"，**禁止写药物剂量**。末尾提示："稳定患者后可回复『继续常规分析』补完整报告"。
3. **已知历史信息抽取**：抽取稳定字段（年龄、性别、妊娠、肌酐/eGFR、肝功能、抗凝史、免疫抑制状态、药物过敏、主要基础病），报告顶部显示一行 `🧾 已知历史信息：...`；无稳定字段则省略。前后不一致时后覆盖前并提示；用户说"换一个/新病例"则清空。
4. **诊断推理（假设-演绎）**：生成 3–7 个初始假设 → 常见病优先（Bayesian）→ 逐一匹配支持项 / 矛盾项 / 未确认项 → 安全网检查（低概率但后果严重者必列）→ 对排名第一的疑似诊断做置信度定级（高 / 中 / 低）。
5. **三层验证门控（输出前必经，任一不通过不得输出）**：
   - 第一层 规则验证（R01–R08）：依据溯源、矛盾检测、重复合并、红旗补充、最低鉴别数（≥3）、缺失路径完整性、概率排序、**置信度门控（R08）**——无当前诊断且最高疑似仅"中/低"时禁止输出疑似诊断报告，强制转缺失信息路径。
   - 第二层 模型交叉验证（质疑者视角，V01–V05）：诊断-证据一致性、鉴别完备性、一元论合理性、严重度匹配、建议可行性。
   - 第三层 输出完整性终检（F01–F07）：每条诊断有依据、依据 100% 可溯源、红旗前置、安全声明已附、格式合规、风险等级已标。
6. **选择输出报告（四选一）**：
   - 命中急症 → 【急症提示报告】（独占）
   - 有当前诊断 → 【鉴别诊断报告】+【误诊/漏诊风险评估】
   - 无当前诊断且最高置信度=高 → 【疑似诊断报告】
   - 无当前诊断且最高置信度=中/低 → 【缺失信息报告】（中：附"仅中等置信初步方向"；低：附"信息严重不足"）

## 输入输出

- 输入：非结构化病历文本 / JSON（症状、指标、检查结果）/ 文件。
- 输出：四类标准化 Markdown 报告之一；每份报告末尾**必须**附安全声明：
  > ⚕️ 以上分析仅供临床决策辅助参考，不构成最终医学诊断。最终诊断须由执业医师结合临床实际做出。
- 语言：输入什么语言就输出什么语言（中/英自动识别，报告模板结构不变，仅文本切换）。
- 质量要求：三层验证必经；只引用用户实际提供的信息（零臆测）；一元论优先；常见病优先；至少 3 个鉴别；推理链路可追溯。

## 注意事项

- 急症提示段"命中即短路"是刻意设计（时间敏感疾病，避免信息淹没救治）。
- 报告中的正式称呼用「急症提示」「已知历史信息」，不使用 Fast-Track / patient_context 等英文技术词。
- 详细规则文档（R01–R08 全文、急症 16 类触发表、15 项临床评分提示、特殊人群 SP01–SP16）未随附文件（未验证是否可获取）。
- 临床评分仅提示应用与覆盖项/缺项，**不代算总分**。

## 可复用示例

用户输入：
```
男，56岁，突发胸痛2小时，位于胸骨后，压榨样，向左肩放射，伴大汗、恶心。
既往高血压10年、2型糖尿病8年，吸烟30年。查体：BP 150/95，HR 98，双肺清。
心电图示 V1-V4 ST段抬高。
```

期望输出要点：命中急症提示 → 仅输出急症卡片（疾病类别：急性 STEMI；时间窗：再灌注 ≤90 分钟内；3 条立即动作：启动导管室 / 心电监护并开放静脉通路 / 立即通知心内科与介入团队），并提示"稳定后可回复『继续常规分析』补完整报告"。
