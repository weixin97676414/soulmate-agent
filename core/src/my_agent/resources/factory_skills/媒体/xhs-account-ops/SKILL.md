# 小红书账号与内容运营分析

目标：**定位清楚 + 内容稳定 + 数据可解释 + 动作可落地**，而不是「多涨粉、多互动」这种空话。

## 一、何时使用

| 用户真实痛点 | 你做什么 |
|---|---|
| 「数据差但不知道哪步出问题」 | 账号与内容运营诊断，定位问题 + 给优化动作 |
| 「想涨粉、想提升互动」 | 账号定位梳理 + 内容结构 + 数据指标解读 + 增长策略 |
| 「不知道发什么 / 内容没规划」 | 内容配比与选题池规划、更新节奏、系列化建议 |

不适用于：需要**真实后台数据**但用户未提供（提示补充，本技能不接入小红书后台，代替不了后台）。

**场景分流（按用户问题对号入座）**：

| 用户问题 | 走哪条 | 参考 |
|---|---|---|
| 账号数据不好 / 没人看 | 数据诊断（逐层定位） | `references/data-diagnosis.md` + `assets/data-diagnosis-table.md` |
| 不知道发什么 / 内容怎么规划 | 内容策划 | `references/scenario-playbooks.md` + `assets/content-calendar-template.md` |
| 账号没定位 / 想做人设 | 定位 | `references/account-operation.md` |
| 想涨粉 / 涨粉慢 | 增长策略 | `references/scenario-playbooks.md` |
| 拆解对标账号 | 对标拆解 | `references/benchmark-teardown.md` + `assets/benchmark-card-template.md` |
| 整体怎么运营 / 做个诊断 | 全流程 | `assets/account-audit-template.md` + `assets/ops-plan-template.md` |

## 二、先补齐输入

账号定位 / 领域、目标人群、发布目的（引流 / 种草 / 涨粉 / 带货 / 品牌曝光）——缺关键输入先问 1~2 个问题，不凭空假设。

- **输入**：目标 + 现状数据（粉丝、近 5~10 篇的曝光 / 点击 / 互动 / 涨粉）+ 账号 / 内容信息。
- **输出**（按模板）：账号诊断报告、运营方案（行动清单）、数据诊断表、内容日历 / 选题池、对标拆解卡。

## 三、执行规范（四块诊断）

用 `assets/account-audit-template.md` 作为报告骨架，逐项填充。方法论细则见 `references/account-operation.md`。

### 1. 账号定位（先想清再发）

**一句话定位 = 你帮谁 + 解决什么 + 凭什么。**

- 人设：你是谁（身份 / 性格 / 审美 / 说话方式）？要有差异化记忆点。
- 领域：一个主赛道，别什么都发，先深后广。
- 目标用户：画像（年龄 / 身份 / 场景 / 痛点 / 消费力）。
- 差异化：同样讲护肤，你的「独特角度 / 理由 / 风格」是什么。

### 2. 内容结构（决定更新与配比）

- 选题池：提前储备 1~2 周选题，按「常青内容 + 热点内容」搭配。
- 内容配比：常见健康比例——**干货 40% + 人设 / 日常 30% + 热点 20% + 转化种草 10%**（按领域调整）。
- 更新节奏：**稳定 > 高频**。宁可一周 2~3 篇保质，也不要每天凑数。
- 系列化：把单篇做成系列，提升收藏 / 关注 / 回访。

### 3. 数据诊断（按曝光→点击→互动→转粉逐层）

| 指标 | 看什么 | 异常含义 |
|---|---|---|
| 曝光 / 阅读 | 笔记被看到多少 | 低 = 选题 / 标签 / 封面没蹭到流量 |
| 点击率 | 封面 / 标题吸引力 | 曝光高但点击低 = 封面标题不行 |
| 互动率 | 赞藏评 / 阅读 | 点击高但互动低 = 正文留不住人 / 不值得赞藏 |
| 涨粉 / 关注 | 账号吸引力 | 互动高但涨粉低 = 人设模糊 / 无系列化 / 引导不够 |
| 收藏率 | 干货程度 | 收藏高 = 有保存价值，利于长尾 |

**诊断顺序**：先看曝光 → 再看点击 → 再看互动 → 再看转粉，逐层定位卡点，不要一锅端。

**数据能算就算，算不了就明确「缺乏数据，请补充」，不编造数字。**

### 4. 对标账号

找定位相近、数据优秀的账号，拆解：人设、选题结构、封面风格、内容配比、更新频率、互动方式。学**框架与逻辑**，不抄袭内容，结合自身差异化做出「你的版本」。

## 四、核心方法：数据诊断漏斗四层（含指标口径）

- **曝光 / 阅读低** → 选题 / 标签 / 封面没蹭到流量。
- **曝光高、点击低** → 封面 / 标题吸引力不足。
- **点击高、互动低** → 正文留不住人 / 不值得赞藏。
- **互动高、涨粉低** → 人设模糊 / 无系列化 / 引导不够。

指标口径：点击率 = 点击 / 曝光；互动率 =（赞 + 藏 + 评）/ 阅读；涨粉率 = 新增关注 / 阅读。口径以平台后台为准，**不用行业均值冒充用户数据**。

判断口径（避免误判）：先看曝光（曝光不过关，后面指标再高也没意义）；区分单篇问题还是账号普遍问题；样本尽量看近 5~10 篇趋势，1~2 篇不足以下结论；**一次只改一个变量**（标题 or 封面 or 选题）才能判断因果。详细拆解见 `references/data-diagnosis.md`，场景打法见 `references/scenario-playbooks.md`。

## 五、常见问题 → 对策

| 症状 | 可能原因 | 动作 |
|---|---|---|
| 阅读长期低迷 | 选题 / 封面 / 标签没对上平台流量 | 换更大众或更垂直的选题，优化封面标题 |
| 曝光高、点击低 | 封面 / 标题弱 | 模仿高互动笔记句式，A/B 多个标题 |
| 点击高、互动低 | 正文差 | 强化前 2 行钩子，给清晰干货与结论 |
| 涨粉慢 | 人设 / 系列化 / 引导缺 | 立人设记忆点、做系列、结尾求关注 |
| 评论区冷清 | 没引导 | 文末抛问题 / 求评，置顶提问，及时回复 |
| 更新断档 | 无选题池 | 提前囤选题，固定更新日历 |

## 六、增长策略（按优先级排序）

1. **把爆款结构固定化**：找到自己跑通过的笔记类型，重复并系列化（最快见效）。
2. **追热点但贴合定位**：蹭热度要能接回你的领域，否则只是热闹。
3. **优化封面 / 标题**：低成本提升点击率的关键。
4. **运营评论区**：置顶 / 精选、及时回复、抛互动问题（冷启动抓手）。
5. **保持稳定更新**：算法看持续输出，稳定账号易获得推荐权重。

## 七、输出规范

- 用 `assets/account-audit-template.md` 结构化输出，给「可直接用」的成果，而非泛泛建议。
- 行动方案用 `assets/ops-plan-template.md`；数据诊断用 `assets/data-diagnosis-table.md`；内容排期用 `assets/content-calendar-template.md`；对标用 `assets/benchmark-card-template.md`。
- 结论给**具体可执行的下一步**，并按优先级排序。
- 明确标注「缺乏数据，请补充」的部分，不虚构。

## 八、交付自查

- [ ] 定位是否一句话讲清（帮谁 + 解决什么 + 凭什么）
- [ ] 是否给了内容配比与更新节奏
- [ ] 数据是否按「曝光→点击→互动→转粉」逐层诊断
- [ ] 每条建议是否具体可执行（不是「优化内容」这种空话）
- [ ] 是否给出了优先级排序
- [ ] 是否虚构了数据（无数据就明说）

## 九、边界

- 不虚构爆款数据、粉丝数、互动量；缺乏数据就明说。
- 不承诺结果，不给「一定爆 / 必涨粉」式承诺，用「有利于 / 提升概率」表述。
- 用户提供的账号 / 数据仅用于本次分析，不外传。
- 不接入小红书后台，不做发布 / 定时 / 后台数据操作。
- 本技能只做**运营分析**；只写文案 / 起标题走文案类功能。

## 十、可复用示例

用户：「我这号最近没人看，帮我诊断」。
做法：先要近 5~10 篇的曝光 / 点击 / 互动 / 涨粉数据 → 按四层漏斗定位卡点（例：曝光高点击低 → 封面标题问题）→ 用 `assets/data-diagnosis-table.md` 输出诊断表 → 用 `assets/ops-plan-template.md` 给按优先级排列的行动清单（如「7 天内改 3 个封面标题做 A/B 测试」）。
