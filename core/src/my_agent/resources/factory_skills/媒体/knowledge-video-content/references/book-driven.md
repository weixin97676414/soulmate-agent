# 书籍驱动内容路径

## 流程
1. 选书 → 2. 深度理解三问 → 3. 提炼核心观点 → 4. 匹配用户痛点 → 5. 选叙事结构 → 6. 写脚本

## 选书标准
- 有明确核心观点（非泛泛而谈）
- 有实验/数据/案例支撑
- 能解决用户正在经历的具体问题
- 优先选择：认知偏差类 > 决策框架类 > 行为改变类 > 商业思维类

## 核心观点提炼方法
**地铁测试法**：如果用户在地铁上只有30秒听你讲，你会说什么？那句话就是核心观点。

- 删除一句不影响理解 → 删
- 最像"正确的废话" → 换具体场景
- 保留的是：用户记不住但应该记住的

## 痛点匹配矩阵

| 书籍类型 | 用户痛点 | 切入方式 |
|:---|:---|:---|
| 认知偏差 | "我为什么总是做错决定" | 帮你看清认知偏差 |
| 行为改变 | "我明知道该做却做不到" | 给可执行的微步骤 |
| 决策框架 | "选择太多反而不知道怎么选" | 提供过滤工具 |
| 博弈策略 | "为什么我总是被套路" | 防身+进攻双视角 |

## 一本书多次使用策略
同一本书可从不同角度产出3-5条内容，参见 [angles.md](angles.md)
