# 短视频爆款拆解与二创

把一条爆款短视频"翻译"成可复用的内容工程图纸：先拿逐字稿，再用抽帧视觉分析拿到真实画面，然后拆拍摄脚本（含真实分镜与可复用拍摄手法）和钩子观点，提炼内容结构框架并做量化评分，再把爆款拆成可反复调用的零件库，最后基于同一框架举一反三产出若干同类型、可直接拍摄的短视频脚本，并把选题沉淀进选题库，形成「拆解 → 零件库 → 二创 → 发布 → 复盘 → 优化」的闭环。

## 适用场景

- 拆解别人的爆款，复制同款脚本。
- 给自己的视频做八维体检、找短板整改。
- 只有一句话想法/主题，要一批选题。
- 长录音（口播/会议/访谈/演讲）拆成多条独立短视频素材。
- 竞品批量分析、跨视频共同框架、发布后复盘。

## 核心原则（质量底线）

1. 有视频文件时，拍摄脚本必须基于**真实画面（抽帧+视觉分析）**，不能只靠口播反推。
2. ASR 转写稿必须先做**语义校正**再用于分析。
3. 二创脚本必须**沿用原片真实拍摄手法**（从抽帧结果继承景别/运镜/构图/色调），并给分镜级拍摄建议。
4. 框架分析必须**量化评分 + 阈值红线**：任一维度 < 3 强制红字提示并给出重写动作。
5. 二创必须配套**发布包装**（标题/封面/发布文案），不是只给文案。
6. **专有名词以画面文字为准**：抽帧后做"读字层"，逐帧读取标题卡/姓名条/logo/鸣谢名单等屏上文字，作为名字/品牌/口号的 ground truth；与 ASR 冲突时以画面文字为准，并产出"屏幕文字台账"。
7. **二创按原片形态自适应**：先按原片时长/结构选模板（短视频单幕 / 中视频双幕 / 中长视频多幕故事）。
8. **二创方向先经用户确认再生成脚本（强制）**：拆完框架、打完 8 维评分后，先产出《二创方向草案》（框架提炼 + 8–12 个候选角度池 + 用户可补充入口），暂停等用户回复，综合"用户勾选 + 用户补充 + 我建议项"确定最终角度集合后才生成完整脚本。
9. **语气与表情是感染力硬指标**：把"话怎么讲、人怎么演"纳入分析，并作为二创复刻信号。
10. **分层级创作，反写守合规**：L1 仿写 / L2 二创 / L3 反写三档并存；L3 反写先给《创作思路说明》经用户确认才出全文，观点不同但必须有理有据、符合底线与价值观。
11. **二创必标平台适配**：每个方案标注所依据的平台规则与适配人群，按视频号/抖音/小红书/公众号分化风格、时长、标题逻辑、互动方式，禁止一稿无差别群发。

## 三条入口：先对号入座

| 你手里有什么 / 想干啥 | 走哪条线 | 主步骤 | 一句话示例 |
|----------------------|----------|--------|-----------|
| 只有一句话想法/主题，要选题或标题 | 轻量选题线 | 0.5 | "帮我围绕『副业踩坑』出 5 个选题" |
| 有别人的爆款视频，想复制同款 | 拆解 + 二创主流程 | 1→2→3→4→5→5.5→6→7→8→9 | "拆解这条，给我 3 条能直接拍的二创脚本" |
| 有自己的视频，数据不好想优化 | 八维自分析 | 1→2→3→4→5→9（+可选 5.8） | "帮我按 8 维看看这条哪里能改" |
| 有对标参考/作战地图，要按参数批量产出脚本 | 批量二创线 | 6.6 | "用老板的口吻改写这条竞品，出 3 条，每条 400–500 字" |

只有逐字稿没有视频时，跳过依赖画面/音频的子步骤（抽帧/视觉/OCR/语气），仍要走说话人配置（按文字稿推断，结论标【推测】）。

## 需求归属确认门（收到内容即先问 · 强制）

收到具体爆款内容（视频文件/链接/逐字稿/爆款文）时，**先让用户选路径，再进入任何分析**，不预设：

1. **拆解爆款二创（复制同款）** —— 逐字稿 + 抽帧视觉分析 → 钩子观点 → 8 维量化评分 → 二创方向草案（暂停确认）→ 分层级二创脚本（L1/L2/L3，默认 5 条）→ 选题库沉淀。
2. **八维自分析（优化你自己的视频）** —— 仅对自有视频做 8 维体检 + 原片整改单，不造新片、不进选题库。

规则：文字类内容（纯文本提问/粘贴逐字稿）直接按常规流程处理，不触发本门；只有视频类内容需先确认归属。用户未选时主动问一句，确认后再进入流程。只发一句话想法要选题 → 走轻量选题线，不进本门。

## 选品对齐门（只拆值得拆的 · 归属① 前置）

拆之前先过"目标用户"这关：人群对不对（是否你未来想服务/成交/长期影响的人）、数据对不对、自己真不真喜欢。

**数据达标门槛（该爆款自身数据）**：

| 形态 | 播放/阅读 | 完播率 | 互动率 |
|------|----------|--------|--------|
| 短视频（抖音/视频号） | ≥ 10 万 | ≥ 30% | ≥ 5% |
| 图文（小红书/公众号） | ≥ 1 万阅读 | — | 点赞率 ≥ 3% |

时效窗口：优先近 3 个月内，半年以上"老爆款"规律可能失效（evergreen 可放宽但标"时效性存疑"）。新号无历史均值时改用上表绝对阈值。数据缺失标【数据缺失】，不编造；明显低于阈值但用户坚持要拆，标【数据未达标·用户坚持】并提示样本偏差风险，不阻断流程。执行原则：**一条拆透，胜过十条拆浅**。

## 决策确认门（二创脚本 & 选题库 · 强制交互）

1. **是否生成二创脚本**（步骤 5.5 用户确认角度之后、步骤 6 之前）：① 生成全套 / ② 仅生成部分 / ③ 暂不生成。用户未明确选择前不得进入步骤 6。
2. **内容是否进入选题库**（步骤 6 之后、步骤 7 之前）：① 建立/更新选题库 / ② 不入库 / ③ 仅挑选部分主题入库。用户未明确选择前不得自动写入。

红线例外：涉及虚假宣传、医疗功效断言、低俗擦边、引战造谣、未标注软广、侵权等，直接拒做或提示风险，无需额外征询。

## 两条线产出边界（防混淆）

| 环节 | 归属① 拆解爆款线 | 归属② 八维评价线 |
|------|-----------------|------------------|
| 二创方向草案（步骤 5.5） | ✅ 必有，暂停等用户选角度 | ❌ 无 |
| 举一反三（步骤 6，默认 5 条） | ✅ 必有 | ❌ 无 |
| 选题库沉淀（步骤 7） | ✅ 有 | ❌ 无 |
| 分平台改进诊断（步骤 5.8） | ❌ 无 | ✅ 有 |
| 异角脚本 | ❌ 无 | ✅ 有（受门管，非二创） |
| 活人感拍摄建议 | ❌ 无 | ✅ 有（仅自有原创视频） |

铁律：归属① 产出结构是"角度池 → 举一反三多方案"；归属② 产出结构是"原片体检单 → 分平台整改建议"，二者结构不同，不可互相替代。跑归属② 时不做任何举一反三；用户若改要"同类型脚本"，说明需求已转向归属①，回到归属确认门重选。

## 分平台改进诊断确认门（八维自分析延伸 · 强制交互）

八维自分析报告产出后，**必须交互询问**是否对原视频做分平台改进诊断：① 做（按抖音/视频号/小红书差异化，执行步骤 5.8）/ ② 暂不做。不得预设"默认就做"。

诊断本质：输入是**原视频本身**，输出是"给这条片子开的分平台体检单 + 整改方案"（拍摄手法怎么调、BGM 怎么配、文案怎么改、平台发布规则怎么适配），目的是优化原片，不是把原视频当素材造三条新内容（那是步骤 6 二创，受二创决策门管辖）。

## 异角脚本选择门（八维自分析延伸 · 确认后执行）

八维报告（含优劣 + 合理化建议）产出后，**必须交互询问**是否要异角脚本：① 要 / ② 不要。不得预设。

产出规范：先拆核心立场（现在站什么角度、想让观众信什么、目标观众是谁）→ 给"相反或不同角度"的拍摄文案（反向立场版 / 不同角度版，可二选一或都给）→ 必须保留原主题价值（换姿势不换话题）+ 给可直接背稿的口播全文 + 说明为什么这个角度可能更稳/更打动人。

护栏：文案须真实可拍、合规，严禁为"反"编造事实、夸大、踩广告法/平台红线；原角度已优则明说"无需反向"，不硬凑；与爆款拆解解耦，不引用/仿写任何外部爆款。

## 活人感拍摄建议确认门（八维自分析延伸 · 确认后执行）

仅归属② 且用户明确要"活人感/拍摄建议"时触发；**绝不进入归属① 拆解二创线**。必须交互询问：① 要（给 6 段方案）/ ② 不要。不得预设。

活人感一句话定义：录内容时，你是对"完成内容"负责，还是对"当下真实的场景与关系"负责。对后者负责 = 活人感。

三纠偏：≠ 反专业（用户想看大咖放松地融入环境演精彩内容）；≠ 随手拍（即兴 solo 靠基本功，活人感比棚拍难一倍）；≠ 必须手机（看对象感）。

6 段方案（输入 = 一条原创视频 brief：主题/计划场景/目标观众/已有脚本可选）：

1. **场景关联诊断**：拿计划场景对照口诀（走着>坐着 / 晚上>白天 / 真实经营场景>固定摆拍），判"预制感"风险（高/中/低），给改场景建议。可用 `scripts/shoot_advisor.py --topic "..." --scene "..." --audience "..."` 半自动出框架。
2. **AI 备课清单**：针对主题/场景列去现场前该问 AI 的 3–5 个具体问题（名字由来/人文/数据/争议），到现场先放真情绪再"说点事"。
3. **情绪锚点**：这条该露的真实情绪（惊/怒/喜/尬/顿悟），以及在场景里怎么被"刺激"出来。
4. **设备建议**：按"对象感"判手机还是 pocket+朋友抓拍，并说明理由。
5. **即兴留白**：指定哪一处故意不准备好（口误/环境干扰/临时起意）作为活人感抓手。
6. **拍完 5 问自检**：真实场景？真情绪？对眼前人说？有即兴痕迹？夹人味？≥3 个"是"= 发。

护栏：建议必须贴"这条具体视频"，严禁只甩通用口诀；不编造情绪；AI 备课只备知识/数据，真情绪永远现场来；不替代专业内容；与爆款拆解解耦。

## 九步流水线

### 步骤 0.5 — 轻量选题

一句话想法/主题 → 五钩子发散出 5 个选题，三段式输出（标题 / 核心观点 / 为什么用户会想看），标题遵循硬规则（≤14 字 / 疑问句或数字 / 规避限流词），复用四基因与成色卡门禁立项。方法见 `references/lightweight_ideation.md`，开口底稿见 `references/hook_opener_examples.md`（大众题材向）与 `references/hook_opener_examples_creator.md`（创作者向）。热点拆题可用四层公式：热点 × 人群 × 痛点 × 解决方案 = N 个贴业务的选题。

### 步骤 1 — 信息抽取

抽帧 + ASR 转写 + 视觉/OCR + 语气表情 + 高光定位，产出逐字稿 + 镜头表。

- 转写用 `scripts/dissect_transcribe.py`。
- 增强方法（说话人分离与质量评分、高光检测、冗余标记、多 ASR 引擎 + 中文 NLP、硬件自适应、PaddleOCR 兜底）见 `references/extraction_enhancements.md`。
- 首次使用可先跑环境自检：`python scripts/check_env.py`（检测 ffmpeg / faster-whisper / reportlab 等依赖）。

### 步骤 1.95 — 说话人配置

判定这条视频几个人在说（S1 单人口播 / S2 双人对话 / S3 多人对话 / S4 旁白+群戏），给每人编号建角色卡。判定依据优先级：抽帧人数 > 声线数 > 回合结构 > 用户描述。角色编号双轨（中文轨 甲/乙/丙 默认、字母轨 A/B/C，同一文档禁止混用；VO 与"众"独立）。规范见 `references/speaker_notation.md`。

### 步骤 2 — 拍摄脚本

按真实画面逐镜拆解，产出镜头表，字段：镜号 / 🗣️ 说话人 / 时间时长 / 景别 / 运镜 / 画面内容 / 台词字幕 / BGM音效 / 备注。备注列三要素：画面来源（原片拆解标【实测帧 0:24】，无画面反推测标【推测】）、可复用手法、拍摄建议。模板见 `references/script_template.md`；景别/运镜/构图/色调/转场词汇与画面配方见 `references/shooting_techniques.md`；剪辑节奏见 `references/editing_design.md`；拍摄形式 F1–F6 见 `references/presentation_form.md`。

### 步骤 3 — 钩子观点

提炼开头钩子 + 核心观点。钩子类型库（悬念/反常识/痛点共鸣/利益承诺/身份代入/冲突对立）与 16+ 种开篇句式模板见 `references/framework_rubric.md`，话术范例见 `references/hook_opener_examples.md`。钩子强度量化 0–100：≥80 强钩子、60–79 中、<60 弱。

### 步骤 3.5 — 标题五维

拆标题的数字/人群/场景/情绪/利益五维，二创标题逐维自查（有标题才走）。

### 步骤 4 — 结构框架

提炼可复用的内容骨架。9 模块框架与 6 种口语化脚本结构见 `references/framework_rubric.md`；结构层"堆信息式 vs 搭结构式"诊断见 `references/twelve_dimension_map.md`。

### 步骤 4.5 — 可调用零件库

把爆款拆成 5 类可反复调用的资产：模板 / 金句 / 内容 / 标题 / 关键词。

### 步骤 5 — 量化评分

8 维打分 + 受众画像 + 阈值红线：

| # | 维度 |
|---|------|
| 1 | 钩子强度 |
| 2 | 信息结构清晰度 |
| 3 | 情绪曲线 |
| 4 | 节奏与完播设计 |
| 5 | 信息密度 |
| 6 | 互动/转化设计 |
| 7 | 可复制性 |
| 8 | 适用赛道与边界 |

每维 1–5 分（可半档）。**任一维度 < 3** → 红字标注短板并给补强动作；**≥2 个维度 < 3** → 提示"框架整体偏弱，二创建议重构而非照搬"。评分标准与补强动作见 `references/framework_rubric.md`。结尾给一句"这个框架强在 ___，复制时要特别注意 ___"。受众画像见 `references/audience_profile.md`；语气表情感染力见 `references/tone_expression_rubric.md`。

### 步骤 5.55 — 二创角度成色打分卡

二创方向立项前的 8 维成色检测（情绪强度/转发动机/独家信息差/身份匹配/时效红利/传播锚点/视觉钩子/行动触发），提分手册与七种情绪档案、基因组合配方见 `references/skill_overview.md` §11 与 `references/framework_rubric.md`。

### 步骤 5.5 — 二创方向草案 & 人工确认（强制暂停）

产出《二创方向草案》：框架提炼 + 8–12 个候选角度池 + 用户可补充入口。**暂停等待用户回复**，综合用户勾选 + 用户补充 + 我建议项确定最终角度集合后，才进入步骤 6。

### 步骤 5.65 — 输出视角三分类

每个二创方案定"以什么身份说"（专家/同伴/旁观）+ 选型理由。

### 步骤 5.8 / 5.85 — 分平台改进诊断 / 12 维度逐项自查（仅归属②）

步骤 5.8：入口层预检（封面+标题）+ 抖音/视频号/小红书三平台诊断 + 整改清单，逐条带时间码。方法与 12 维度（5 阶段：刷到 → 看完 → 转发 → 记住 → 变现，每项 0–5 分，总分 60，<36 列优先整改项）见 `references/twelve_dimension_map.md` 与 `references/platform_rules.md`。

### 步骤 6 — 举一反三：生成同类型脚本（受二创脚本门管）

按确认方向写带分镜的成稿脚本，默认 5 条，分层级 L1 仿写 / L2 二创 / L3 反写。写脚本前先按"12 种爆款结构速查索引"定结构类、再定句式，并用 CREA 最小骨架（结论→理由→例子→行动）逐句落地。模板见 `references/script_template.md`；12 种结构、4 维度选用决策树、热点→结构翻译器、换壳换行业迁移见 `references/framework_rubric.md` §五/§六；BGM 设计见 `references/bgm_design.md`；母素材深挖（一条素材拆成 N 篇内容矩阵）见 `references/source_material_matrix.md`。

### 步骤 6.6 — 批量二创（参数化对标改写）

当需求是「按固定参数批量产出脚本」而非逐条人工定角度时（如出镜人 IP 量产、竞品口吻复刻、作战地图落地），走参数化批量生成。它用一组参数把**口吻对标 / 内容对标 / 历史风格参考**清晰分开：

| 模式 | 触发条件 | 行为 |
|------|----------|------|
| 自由创作 | 无任何对标/参考 | 依据基础信息原创 |
| 口吻对标 | 提供「口吻对标」参考文件 | 严格模仿该文件里人物的说话方式 |
| 内容对标 | 提供「内容对标」参考文件 | 严格模仿该文件的结构、主题、节奏 |
| 混合对标 | 两者都给 | **用 A 的口吻去改写 B 的内容** |

任一模式下若提供「历史文案」，需参考其风格并确保新脚本选题不与历史重复。

**SOP（不得跳过确认）**：① 构建参数 → ② 把整理好的参数列表发回用户审核 → ③ 暂停，等用户回复「可以 / 继续」 → ④ 确认后按 `references/对标创作提示词模板.md` 的框架，用下列参数直接生成脚本，全部在本机完成。

| 参数 | 必填 | 说明 |
|------|:--:|------|
| 生成脚本数量 | 是 | 要产出的脚本条数 |
| 字数范围 | 是 | 每条脚本的最少 / 最多字数 |
| 出镜人名称 | 否 | 出镜人名称 |
| 客户背景 | 是 | 客户背景描述（含出镜人人设） |
| 核心产品 | 否 | 核心产品一句话简述 |
| 额外要求 | 否 | 额外的、一次性的文案要求 |
| 作战地图文件 | 是 | 作战地图（核心策略）文件路径 |
| 会议纪要文件 | 否 | 会议纪要（内容要点）文件路径 |
| 产品介绍文件 | 否 | 产品详细介绍文件路径 |
| 口吻对标文件 | 否 | 口吻对标参考文件 |
| 内容对标文件 | 否 | 内容对标参考文件 |
| 历史文案文件 | 否 | 历史文案文件列表（参考风格、避免重复） |

支持的输入格式：`.pdf` / `.docx` / `.md` / `.txt`，均在本机读取解析。

**输出格式**：Markdown，多条脚本之间用 `---` 分隔，每条严格包含：

```
### Script N: [脚本标题]

**核心卖点**: [该脚本聚焦的核心卖点]
**目标用户**: [该脚本主要面向的用户群体]

**[黄金三秒]**
（钩子文案）

**[主体内容]**
（主体文案）

**[引导行动]**
（结尾引导文案）
```

**注意**：生成的文案中禁止出现「作战地图」「作战室」字样；文案须符合平台标准、不能违规，如需变现加入适当转化钩子。创作提示词模板见 `references/对标创作提示词模板.md`，落笔规范见 `references/script_template.md`。

## 好故事哲学 · 创作校准

工程化的门禁（四基因、12 心法、成色卡、合规门）管的是"不翻车"；以下约束的是"能打动人"：

1. 禁止用公式代替创作——公式是工具不是目的，打动人的永远是真实情感。
2. 真实 > 编造——素材里真实的一句话，胜过十句精修的空话。
3. 克制的叙事打动人——一个停顿、一个细节，比煽情更戳人。
4. 笨功夫击败流水线——用心的"笨"在 AI 批量生产时代是稀缺价值。
5. 避免惰性创作——每次二创完成前都问"这条里有我真实的思考吗"。
6. 把目光从流量数据转向真实生活——先想"有没有真实生活里朴素、动人、有力量的东西"，再谈指标。
7. 观众能分清刺激与触动——优先做"触动"而非"刺激"（分数达标 ≠ 打动人）。
