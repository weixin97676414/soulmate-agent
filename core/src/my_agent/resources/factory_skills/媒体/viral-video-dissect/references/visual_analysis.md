# 抽帧与视觉分析细则（visual_analysis）

本文件供 `video-script-dissect` 技能在「步骤 1.8 视觉分析」与「步骤 1.5 语义校正」中参考。

---

## 一、抽帧方法（场景切分优先）

**核心原则**：多场景/长视频不能靠"均匀抽帧"——均匀抽样会漏掉幕切换点，导致镜头表断裂、叙事幕判断错误。优先用**镜头边界检测**按真实切点抽帧。

### 方式 A：ffmpeg 镜头边界检测（推荐，长视频/多场景必用）
```bash
# 检测场景切换点并逐切点抽帧（scene 阈值通用 0.3）
ffmpeg -i input.mp4 -vf "select='gt(scene,0.3)',showinfo" -vsync vfr frames/frame_%04d.png
```
- 解析 stderr 中 `showinfo` 输出的 `pts_time`（或帧号），得到切点时间列表。
- 按切点抽帧；**上限 ~24 张**，超过则对切点做均匀子采样（保留首尾与中段代表帧）。
- 阈值调整：快剪片降 `0.2`（切镜更密），慢/固定镜头片升 `0.4`（避免误判）。

### 方式 B：均匀抽帧（兜底，仅纯固定镜头）
```bash
# 场景检测结果为 0 张时回退均匀抽帧
ffmpeg -i input.mp4 -vf "fps=1/10" frames/frame_%03d.png
```
均匀抽帧密度建议：

| 视频类型 | 建议间隔 | 说明 |
|----------|----------|------|
| 态度/情感独白（慢） | 每 8–12 秒 | 镜头少、留白多，按情绪段抽即可 |
| 口播干货/教程 | 每 5–8 秒 | 切换较频繁 |
| 快剪/Vlog | 每 3–5 秒 | 切镜极快，需更密 |

### 音频提取给 ASR
```bash
ffmpeg -i input.mp4 -ar 16000 -ac 1 audio.wav
```

### 方式 C：无 ffmpeg，改用 imageio-ffmpeg（Python 兜底）
```python
import imageio_ffmpeg, subprocess, os
ff = imageio_ffmpeg.get_ffmpeg_exe()
os.makedirs("frames", exist_ok=True)
subprocess.run([ff, "-i", "input.mp4", "-vf", "select='gt(scene,0.3)',showinfo",
                "-vsync", "vfr", "frames/frame_%04d.png"])
subprocess.run([ff, "-i", "input.mp4", "-ar", "16000", "-ac", "1", "audio.wav"])
```

> **长视频（>3min）/多场景视频强制场景检测**：华为坤灵那条 5 分钟、多幕、多角色视频，均匀抽 14 帧漏掉了若干幕切换点；改用场景检测后帧数覆盖到真实切点，叙事幕判断显著更准。

## 二、屏幕文字优先（专有名词 ground truth，必做）

抽帧后做**强制读字层**——逐帧读取画面上的所有文字。这些文字是名字/品牌/口号的**权威来源**，**一旦与 ASR 冲突，一律以画面文字为准**。

### 必须读取的屏上文字类型
- **标题卡 / 片名**：如"老沈的生意经""极狐 V9"。
- **人物姓名条 / 身份条**：如"老沈 · 弱电工程商 20 年"（ASR 可能听成"老陞""老魏"）。
- **品牌 logo / 产品名**：如"华为坤灵 / HUAWEI eKit"（ASR 可能听成"坤林"）。
- **下三分之一字幕中的关键词放大**：常为 slogan。
- **结尾鸣谢 / 名单 / 分屏证言卡片文字**。

### 产出：屏幕文字台账
| 时间码 | 屏上文字 | 类型 | 与 ASR 冲突处理 |
|--------|----------|------|----------------|
| 0:08 | 老沈的生意经 | 片名 | — |
| 0:15 | 老沈 · 弱电工程商 | 姓名条 | ASR"老陞"→ 以画面"老沈"为准 |
| 2:10 | 华为坤灵 HUAWEI eKit | logo | ASR"坤林"→ 以画面"坤灵"为准 |

> 本环境用视觉读取（Read 逐帧图）实现"读字层"，无需额外 OCR 依赖。若运行环境可装 `tesseract` + `pytesseract`，可用其程序化兜底（对批量视频更高效）。

## 三、逐帧视觉分析清单

对每一帧（或代表性帧）输出以下要素，形成"时间→画面要素"映射表：

- **景别**：全景 / 中景 / 近景 / 特写 / 过肩 / 大特写
- **运镜**：固定 / 推 / 拉 / 摇 / 移 / 手持 / 升降 / 航拍
- **构图**：中心 / 三分法 / 对称 / 留白 / 前景遮挡
- **主体**：人物（单人/双人/分屏多人）、产品、空镜（海浪/车流/城市）、文字卡
- **字幕样式**：是否有字幕、位置（上/下）、字号、是否关键词放大/变色
- **色调**：暖/冷/高对比/低饱和/暗调/明亮
- **辅助元素**：B-roll 空镜、分屏、贴纸、转场特效、logo/结尾页
- **与口播对齐**：该帧对应的台词/情绪（结合 ASR 时间戳）

**输出格式示例**：
| 帧 | 时间 | 景别 | 运镜 | 画面 | 字幕 | 色调 |
|----|------|------|------|------|------|------|
| frame_003 | 0:24 | 近景→特写 | 缓推 | 主角眼神光，背景虚化 | "定力"放大 | 暗调暖光 |

这张表就是步骤 2「拆解拍摄脚本」的**事实依据**——能直接对应到镜头表的景别/运镜/画面内容列。

## 四、ASR 语义校正（步骤 1.5）

### 为什么必须做
faster-whisper 在以下场景误识率高：轻声/气声、背景音乐、方言、专有名词、数字、同音/形近字。直接拿转写稿分析会把错词当真，污染后续框架与钩子判断。

### 校正流程
1. 通读转写稿，标出"语义不通/不像人话"的可疑词。
2. 结合**语气、上下文、常识、画面文字（见第二节台账）**推断正确词。
3. 在报告中列出修正点：`原词 → 校正词（理由）`。
4. 标注【ASR误识·已校正】；仍不确定者标【存疑】，不强行定论。

### 附录：常见误识类型与示例
| 类型 | 误识 → 正解 | 示例 |
|------|-------------|------|
| 同音字 | 操载 → 喧嚣 | "远离操载"→"远离喧嚣" |
| 形近/音近 | 寒冻 → 撼动 | "未被寒冻"→"未被撼动" |
| 轻声吞音 | 严说 → 言说 | "不必严说"→"不必言说" |
| 轻声吞音 | 手静 → 守静 | "手静于心"→"守静于心" |
| 专有名词 | 品牌/人名错写 | **以画面文字台账为准**（如"坤林"→"坤灵"） |
| 数字 | 金额/年份错 | 结合行业常识核对 |

> 经验：诗意独白、广告 slogan、歌词类内容误识最严重，务必逐句校对；若有原始台词本/字幕文件，以原始为准替换。
