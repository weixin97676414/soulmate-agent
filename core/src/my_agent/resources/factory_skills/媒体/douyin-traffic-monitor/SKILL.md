# 抖音流量监控

## 执行目标

输入账号数据、视频指标、直播数据和观察周期，产出流量趋势、异常告警、来源拆解与行动建议，适合抖音运营、直播团队和负责人。用于抖音流量监控任务，并输出证据、风险和验收状态。

## 必填输入

- 核心资料：账号数据、视频指标、直播数据和观察周期
- 业务目标：期望解决的问题、渠道、时间范围与成功标准
- 事实边界：可引用数据、禁止内容、隐私与合规限制
- 交付要求：文件格式、目标系统以及是否允许外部写入

缺少关键事实时，先列出缺口并给出可安全继续的最小方案。不得补写价格、销量、评价、功效或平台状态。

## 标准流程

1. 核对输入来源、时间范围、目标对象、授权边界与指标口径。
2. 将信息拆为已知事实、待验证假设、限制条件、风险和行动项。
3. 围绕"抖音流量监控"先生成结构，再补充能追溯到输入的细节。
4. 执行专项方法：建立发布、直播和投流基线，按小时或日识别显著变化；缺少平台实时权限时明确数据延迟。
5. 产出流量趋势、异常告警、来源拆解与行动建议，为关键判断记录来源、计算口径或推导过程。
6. 检查完整性、冲突、重复、可执行性和合规风险，形成逐项验收状态。

## 交付结构

1. **结论摘要**：三到五条最重要判断。
2. **主交付物**：流量趋势、异常告警、来源拆解与行动建议。
3. **证据与口径**：资料来源、日期、计算方法和未验证项。
4. **风险与阻断**：影响、优先级、解除条件与负责人建议。
5. **下一步动作**：对象、动作、截止条件和验收信号。

## 质量门槛

- 输出语言、字段和行动顺序适合抖音运营、直播团队和负责人。
- 事实、数字、案例和承诺有来源；无来源时明确标注"未验证"。
- 每条建议包含对象、动作、原因和验收信号，不只给泛化观点。
- 重复内容合并，冲突内容并列说明，不靠换词制造虚假差异。
- 涉及发布、发送、付款、删除、权限、账号或隐私时，确认用户授权和目标系统状态。
