# 快速上手指南规范

阶段6 使用。对应验收标准「上手指南内容正确，且容易理解」。

## 六段结构（顺序固定）

```markdown
## 1. 环境准备      ← 版本要求与检查命令
## 2. 获取代码      ← clone / 下载 / 引入依赖
## 3. 构建          ← 构建命令与常见失败处理
## 4. 跑起来        ← 启动命令
## 5. 验证          ← 看到什么算成功
## 6. 下一步        ← 按目标分支的进阶路径
```

## 每段的写法

### 1. 环境准备

给出**检查命令**，不是"需要 Java 8 以上"：

```bash
java -version    # 要求 17+，Spring Boot 3.x 基线是 17；输出 1.8 需升级
mvn -version     # 要求 3.6+
```

版本号要说明**为什么是这个版本**（如"Spring Boot 3.x 基线是 17"），不是干巴巴一个数。

### 2. 获取代码

区分两种用户：

```bash
# 只想用
<dependency>...</dependency>

# 想看源码/二次开发
git clone <url> && cd <dir>
git checkout <具体 tag>   # 不要用 main，main 可能不稳定
```

### 3. 构建

```bash
mvn clean install -DskipTests
# 若报 "maven-compiler-plugin 版本冲突"，先执行 mvn -U clean
```

**命令要带失败处理。** 常见失败（网络超时、版本冲突、缺系统库）就写在下面。

### 4. 跑起来

给出启动命令 + 关键日志：

```bash
mvn spring-boot:run
# 或 java -jar target/demo.jar
```

### 5. 验证（最关键）

**具体到可观察的字符串**：

```bash
curl http://localhost:8080/di/constructor
# 预期：{"injectionType":"constructor"}
# 若返回 500 → 看日志里的异常类名，对照踩坑点 N
```

不写"如果能正常访问就说明成功了"。

### 6. 下一步

按目标分支：

| 目标 | 建议 |
|------|------|
| 概览 | 读架构章节，跑一遍 Demo |
| 集成 | 从能力清单挑需要的，改 Demo 试 |
| 二次开发 | 看扩展机制章节 + 本地调试方法 |
| 排障 | 直接翻踩坑点 |

## 可读性的硬要求

1. **命令优先于文字** —— 能用一段命令说清的，不写三行散文
2. **每个命令配预期输出** —— 用户才知道自己成没成
3. **版本号写全** —— "Java 17" 不写 "新版 Java"
4. **失败处理内联** —— 每个可能失败的步骤下面紧跟"如果报错怎么办"
5. **不跳步** —— 假设读者从零开始，`cd` 到哪、`export` 什么都要写

## 优质判据

- [ ] 六段齐全，顺序正确
- [ ] 环境要求给了检查命令且说明版本理由
- [ ] 每个命令有预期输出或验证方法
- [ ] 常见失败场景有对应处理
- [ ] 命令可直接复制执行（无 `<占位符>` 未替换）
- [ ] 新人照着做能一次跑通（自己按步骤验一遍）

## 常见错误

- ❌ 只写命令不写预期输出（用户不知道成功长什么样）
- ❌ 环境要求写"最新版"（会过时）
- ❌ 省略 `cd` 等上下文（复制执行就失败）
- ❌ 没有失败处理（一步失败就卡死）
- ❌ 验证步骤写"访问首页看看"（不可判定）
