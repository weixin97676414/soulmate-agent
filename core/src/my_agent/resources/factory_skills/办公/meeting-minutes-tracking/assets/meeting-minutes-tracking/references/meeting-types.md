# 三类会议特征对照

> 用于：
> - Planner 在 Plan 阶段判定会议类型 → 决定 memory 切片归档目录
> - Researcher 切片时按类型抓重点字段
> - Executor-A 调整议题排序与详略
> - Executor-B 跨会议调取时按类型加权

---

## §1 类型一：销售会议（sales/）

### 典型场景
- 客户拜访 / 客户回访 / 提案沟通
- 报价讨论 / 合同条款谈判 / 续约 / 扩单
- 客户内部决策链沟通

### 必抓字段
- 客户表态（明确同意 / 明确拒绝 / 模糊）
- 报价与价格谈判过程
- 签约推进节点（合同进度 / 法务审查节点）
- 续约 / 扩单意向
- 客户内部反对意见 / 支持人

### 易漏字段
- **客户原话情绪信号**——不只是说了什么，还有语气（强烈 / 试探 / 让步）
- **未明说的拒绝信号**——"我们再考虑下" 往往是软拒
- **决策链中的暗线**——"老板那边可能不同意" 这类
- 客户给的"行业横向参考"（他知道竞争对手报多少）

### Executor-A 议题排序
- 客户最终表态在前
- 商务条款在中
- 内部反对意见单列
- 我方下一步动作清单结尾

### Executor-B 跨会议调取重点
- 同一客户多场销售会议看：客户态度变化曲线 / 报价让步幅度 / 决策周期

---

## §2 类型二：经营分析会议（ops-review/）

### 典型场景
- 月度 / 季度 / 半年 / 年度经营回顾
- KPI 完成度评审
- 业务板块经营状况复盘
- 财务数据走读

### 必抓字段
- 数据口径（同比 / 环比 / 累计 / 当期）
- 数据时点（截至 X 月 X 日 / 全口径 / 不含 X）
- KPI 完成度 + 缺口 + 归因
- 预算调整决议
- 经营层分歧（哪个板块谁主张哪种调整）

### 易漏字段
- **数据时点切换**——同一指标在不同人嘴里口径不一致
- **归因分歧**——业绩下滑甲方说市场，乙方说执行
- **数据真实性的"软"质疑**——"这个数算上 X 之后好像偏乐观"
- **预算调整的连带影响**——某板块预算砍了对其他板块的牵连

### Executor-A 议题排序
- 财务总览在前
- 各业务板块分别详述
- 跨板块共性问题
- 整体决议 + 行动项

### Executor-B 跨会议调取重点
- 季度连续会议看：KPI 完成度趋势 / 归因一致性 / 预算调整累计幅度

---

## §3 类型三：项目管理会议（project-mgmt/）

### 典型场景
- 项目周会 / 双周会 / 月度评审
- 阶段评审会 / 里程碑会议
- 风险评审 / 变更评审 / 验收会议

### 必抓字段
- 任务进展（完成 / 进行中 / 未启动 / 阻塞）
- 阻塞具体到节点（在 X 部门 X 人手里）
- 风险（已发生 / 潜在 / 关闭）
- Deadline 调整（原 / 现 / 变更理由）
- 人手 / 资源调配
- 跨部门交接情况

### 易漏字段
- **风险责任人**——风险登记表往往无 owner
- **阻塞的"前一手"**——A 被阻是因 B 没出资料，B 没出是因 C 没批
- **变更的连锁影响**——一个任务延期对下游 5 个任务的影响
- **资源冲突**——同一人在两个项目都被排满

### Executor-A 议题排序
- 阻塞 / 风险优先
- 关键路径任务在前
- 普通进展跟新在中
- 资源 / 跨部门事项单列
- 下次会议预读结尾

### Executor-B 跨会议调取重点
- 项目连续会议看：阻塞演变 / Deadline 推迟累计 / 风险升降级

---

## §4 类型边界

| 边界场景 | 归类 | 理由 |
|---|---|---|
| 销售部门内部讨论某客户报价 | sales | 虽内部，但围绕客户决策 |
| 公司战略规划会 | other（暂归未分类） | 不属于三类之一 |
| 客户参加的项目里程碑评审 | project-mgmt | 项目治理优先 |
| 月度经营分析中讨论某客户 | ops-review | 经营视角主导 |
| 一对一深度访谈 | **不归本技能** |

---

## §5 跨类型的共性硬约束

无论何种类型，会议纪要必有：
- 7 字段基本信息表
- 议题 → 决议 → 行动项三段（行动项含四要素）
- 未核实清单附录

任何类型差异仅影响"必抓字段重点"和"议题排序"，不影响"完整性硬标准"（见 RULES.md §3）。
