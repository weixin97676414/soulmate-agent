# 切片 frontmatter schema（v1.5）

> 入库切片的 YAML frontmatter 字段规范。`meeting-minutes-tracking` 入库时按此 schema 写；跨场问询 / 简报读时按此 schema 提取。
> v1.5 新增选填字段 `说话人口音:`，供 §2.5 转录校对建口音画像。

---

## §1 完整 schema

```yaml
---
客户: 甲方A                          # 必填 · 客户代号（不写真名）
工作类型: ops-review                  # 必填 · enum 8 选 1
工作主题: 2026Q2业绩盘点              # 选填 · 简报合成主题键；空时退化为工作类型默认名
日期: 2026-05-15                     # 必填 · YYYY-MM-DD
时间窗: 2026-05-15 ~ 2026-05-15      # 选填 · 单场会议同日期；多日工作填范围
我司主笔: P-CON-钱                    # 推荐 · 主要参与/记录的咨询顾问代号
原始来源: outputs/_smoke/transcript-...md   # 推荐 · 文字稿/录音转写文件路径
说话人口音: P-财务总监-张=湖南          # 选填 · 与会者代号=籍贯/口音；多人用逗号分隔，供 §2.5 口音画像
入库时间: 2026-05-17                  # 自动 · meeting-minutes-tracking 入库时写

# ===== Executor-C 简报合成器抽取字段（v1.3 新增）=====
相关产出物:                          # 选填 · list[str]，简报"相关文件"展开
  - 《XXX 报告 V2》
  - 《YYY 分析 V1》
我方观察建议: |                      # 选填 · 简报"备注/建议"段（括号包裹）
  ……（自由文本，含明确语气词如"建议..."、"未达成共识"等）

# ===== 可选关系字段 =====
participants: [...]                  # 选填 · 与会者代号列表
project: 项目X                       # 选填 · 项目代号
tags: [...]                          # 选填 · 自由 tag
related_meetings:                    # 选填 · 关联其他切片的相对路径列表
  - 2026-04-10-甲方A-ops-review-Q1预算.md
---
```

## §2 工作类型枚举（必须严格匹配）

| 值 | 中文名 | 切片放哪 |
|---|---|---|
| `sales` | 销售会议 | `sales/` |
| `ops-review` | 经营分析会 | `ops-review/` |
| `project-mgmt` | 项目管理会 | `project-mgmt/` |
| `research` | 调研/资料梳理 | `research/` |
| `site-visit` | 现场走访/参观 | `site-visit/` |
| `process-mapping` | 流程梳理工作坊 | `process-mapping/` |
| `policy-design` | 制度/方案设计 | `policy-design/` |
| `other` | 其他 | `other/` |

## §3 切片正文结构（frontmatter 之后）

```markdown
# {客户} {时间} · {主题}

## §1 议题速记
（3-5 行 bullet · 该场会议/工作的核心主题）

## §2 决议要点
（编号清单 · 每条带紧急度 / 影响面标注）

## §3 行动项跟踪表
| # | 内容 | 责任人 | 追踪人 | Deadline | 我方角色 | 状态 |
|---|---|---|---|---|---|---|
| A1 | ... | ... | ... | YYYY-MM-DD | 我司独立交付 / 联合主导 / 配合 / 观察 | pending / in-progress / done |

## §4 我方承诺未交付项（跨场问询最高优先扫描位）
- {明确承诺但未落地的事项 + 紧急度信号}

## §5 风险与信号
- {可能升级的问题 + 我司可介入的增项机会}

## §6 索引关键词（便于跨场 grep + 简报主题聚类）
`关键词1`, `关键词2`, `关键词3`, ...

## §7（可选）子事项归并（供简报合成器引用）
（按子主题列出本场涉及的多个日期-动作）
```

## §4 校验规则（client-memory-mgmt 用）

| 项 | 通过线 |
|---|---|
| frontmatter YAML 解析无错 | ✅ |
| 必填字段（客户/工作类型/日期）都在 | ✅ |
| `工作类型` 是 8 类枚举之一 | ✅ |
| `日期` 是 YYYY-MM-DD | ✅ |
| 正文含 §1-§5（§6 §7 可缺）| ✅ |
| 行动项 §3 表头 5 列齐全（# / 内容 / 责任人 / 追踪人 / Deadline）| ✅ |
| 客户代号在 `client-codename.md` 中已登记 | ✅ |

任一不过 → 出补全清单交用户决策；**不自动修改切片**。

## §6 版本化

- 切片**不修改**——发现错误起 v2：`YYYY-MM-DD-{slug}-v2.md`
- 旧版本 frontmatter 加 `deprecated: true / superseded_by: v2.md`
- 多次修订后旧版归档 `_legacy/`

---

## §7 文件命名

```
YYYY-MM-{slug}.md                       # 月度聚合切片（如甲方X反向拆的"2025-11-战略规划会议.md"）
YYYY-MM-DD-{slug}.md                    # 单场切片
YYYY-MM-DD-{slug}-{seq}.md              # 同日多场加序号
YYYY-MM-DD-{slug}-v2.md                 # 修订版本
```

`{slug}` 用 1-4 个汉字概括核心，≤12 字符；不用拼音。
