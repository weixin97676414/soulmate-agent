# 交付物挖掘规则（v1.1）

> 当用户问"甲方 X 在 Y 时段做了什么 / 交付了什么"时，按本规则扫描 + 分桶 + 输出。
> 实现位置：`shared/deliverable_mining.py` · `scan_deliverables(project_root, client_code, start, end)`
> 调用方：跨场问询直接答 / 简报在附件区自动汇总

---

## §1 4 个数据源（合并 + 去重）

### §1.1 outputs/{客户}/ 下的真实 docx/xlsx/pptx
- 按 mtime 过滤时段
- 跳过 `~$*` `._*` 等临时文件
- 输出含路径 + 字节大小 + 修改时间

### §1.2 切片 frontmatter `相关产出物` 字段
- 列出的产出物路径/书名号文件名
- 时段过滤：以切片 frontmatter `日期` 字段为准（月度切片用月中 15 日作 proxy）
- 输出不含字节大小（仅参考）

### §1.3 切片 §3 行动项跟踪表 "我方角色" 列
- 含 `我司独立交付 / 我司联合主导 / 我司主导` 关键字的行
- 这些**非文件类**事项放进独立桶
- 输出含动作内容 + 来源切片

### §1.4 outputs/{客户}/_files/ 项目过程文件（如有）
- 同 §1.1 处理逻辑
- 通常装放未外发的工作底稿、模板、参考资料

---

## §2 3 类分桶 + 1 桶独立事项

### §2.1 主交付物（main）
**判定**：文件名含 `定稿 / 正式版 / 外发版 / 终稿 / Final / FINAL` 任一关键字。
**意义**：是真正交给甲方的成果。

### §2.2 工作中间产出物（intermediate）
**判定**：文件名含 `V1 / V2 / V3 / V4 / 草稿 / 共识稿 / 工作底稿 / 讨论稿 / 测算` 任一关键字。
**意义**：项目过程中的迭代版本；内部用 / 联合调试用。

### §2.3 待分桶（unclassified）
**判定**：上面两个分桶规则都不命中。
**意义**：通知 / 报告 / 登记表等中性文件——交项目组审时手工确认归类。

### §2.4 我方独立完成事项（independent_items）
**判定**：切片 §3 行动项跟踪表中 "我方角色 = 我司独立交付/联合主导" 的非文件类事项。
**意义**：项目组实际做了但不一定形成文档的工作（如"出培训排期"、"汇报"、"沟通"）。

---

## §3 去重规则

按 normalized filename（去空格 + 小写 + 去书名号）做 key 去重：
- 同名条目优先取**有 outputs 真实路径**的（更可信）
- 文件名变体（如《XXX V1》 vs 《XXX V1》）按 normalized 视为同一文件
- 跨切片重复引用同一文件 → 保留首次出现的 source 标注

---

## §4 输出格式（跨场问询调用时严格遵循）

```markdown
## 甲方 X · YYYY-MM-DD ~ YYYY-MM-DD 交付清单

> 共扫到 outputs 真实文件 N 份 + 切片产出物字段 M 项；去重后 N' 份；我方独立事项 K 条

### §1 主交付物（外发给甲方 · 含 定稿/正式版/终稿/Final 关键字）
- 《XXX 报告 V2 定稿》 [2025-11-18 · 1234 KB] · 来源: outputs/真实文件
- ……

### §2 工作中间产出物（V1/V2/草稿/工作底稿/测算）
- 《XXX 测算 V3》 [2025-11-25] · 来源: 切片 frontmatter 2025-11-XXX.md
- ……

### §3 待分桶（项目组审时确认归类）
- 《XXX 通知》[2025-11-05] · 来源: ...
- ……

### §4 我方独立完成事项（来自切片 §3 行动项 · 非文件类）
- {事项摘要} · 来源切片：`xxx.md`
- ……
```

---

## §5 红线（不可豁免）

- ❌ **不能编造文件名**——必须能在 `outputs/` grep 到，或在切片 frontmatter `相关产出物` 中找到
- ❌ **不能跨客户合并**——一次只扫一个客户目录
- ❌ **不能把真名暴露在输出里**——客户用代号；如用户明示"用真名说"，仅口头回，**不写入持久化文件**
- ❌ **不能把 outputs/{客户}/raw/ 下的甲方原始资料当作我司交付物**——这些是输入资料不是输出
- ❌ **不能把已 deprecated 的旧切片纳入扫描**——`_legacy/` 目录跳过

## §6 与 work-brief 简报附件区的衔接

简报生成在步骤 6 "Deliver 前" 调用本规则：

```
client_code = "甲方B"
start = "2025-11-01"
end = "2025-11-30"

result = scan_deliverables(project_root, client_code, start, end)

# 简报附件区按 3 类分桶组织：
# §6.1 → main 桶 → "（一）{主题 1} 主交付物"
# §6.2 → intermediate 桶 → "（二）{主题 N} 工作中间产出物"
# §6.3 → unclassified 桶 → 提示用户人审分桶
# §6.4 → independent_items → 简报正文"主题块"日志条目补强
```

外发简报通常**只列 main 桶**——intermediate 桶给内部留档版使用。

---

## §7 与跨场问询 5 项清单的关系

5 项清单聚焦**问题与待办**；交付物挖掘聚焦**已做的工作**。

| 用户问 | 走哪个能力 |
|---|---|
| "甲方 X 最近有什么问题需要我们配合" | 4 维优先级排序 → 5 项清单 |
| "甲方 X 在 Y 时段做了什么 / 交付了什么" | 交付物挖掘 → 3 桶清单 |
| "我们 Q2 给甲方 X 出了哪些报告" | 交付物挖掘 + 时段过滤 |
| "甲方 X 反复在催什么" | 5 项清单（紧急度维度） |
| "下次会议要重点跟进的事" | 5 项清单 + 交付物挖掘联动 |

两个能力**共用切片库**但**不互相调用**——避免循环依赖。

---

## §8 性能与可靠性

- 单客户单时段扫描 < 1 秒（基于现有 5-50 份切片规模）
- 切片解析失败（yaml 损坏）→ 跳过该切片 + 日志告警，不阻塞整批
- outputs 目录不存在 → outputs 部分返回空，slice 部分照样扫
- 客户代号在 `client-codename.md` 中未登记 → AskUserQuestion 引导走 `client-memory-mgmt` 登记

---

## §9 用户审用关键问题

输出 3 桶后，项目组审用时常问：

1. **§3 待分桶里的文件应该入主交付物还是中间产出物？** → 看是否对外发出，对外发出 → main
2. **某份《XXX V3》是定稿吗？** → 看版本号是否冻结，冻结 → main；还会迭代 → intermediate
3. **独立事项怎么变成简报日志？** → 调用 `to_brief_log_line()` 格式化为"{月}月{日}日，{动词}{对象}"
