# 项目实体核验 · 台账/别名/roster 三级匹配

> 适用：周期性例会（周例会/月度例会）或任何**存在基准台账、别名表、固定 roster** 的场景。
> 目标：转写中出现的客户名、项目名、项目号、人名、职务、金额，用项目证据逐一定案——
> **确证的静默改，拿不准的一次问用户，正式纪要不留任何纠错痕迹。**

与 §2.5 转录文字校对的分工：
- §2.5 管**语言层**（错别字/同音词/断句/标点）——通用规则直接改。
- 本规则管**项目层**（专名/金额/编号）——必须过证据核验，**通用语言判断不能单独作为专名修改依据**。

## 一、抽取对象（从清洗稿抽出全部高风险实体）

- 客户名 / 项目名（含简称、近音词）
- 口语项目号（"422""439"这类 3–4 位代号）
- 金额、比例、日期、验收/回款/交付节点
- 人名、职务、负责人、追踪人

## 二、三级匹配（按序执行，命中即停）

1. **别名表**：客户 README/`术语表.md`/auto-memory 中已登记的"误听→标准名"映射，命中 → **确证**，静默用标准名。
2. **基准台账检索**（脚本见下）：
   - 在台账的 `客户名称 / 项目名称 / 唯一编号` 列检索；
   - 口语项目号 "NNN" → 拼成台账编号格式（如 `SDQR-0NNN`）再查唯一编号列；
   - 唯一命中 → **确证**；多个候选 → 不确证，进待确认。
3. **Roster 核验**：人名与职务按固定与会名单唯一命中后纠正。
4. 都没命中或多个候选 → **不确证**，进入待确认清单。

## 三、确证与问询判定

| 情形 | 处理 |
|---|---|
| 别名表命中 | 静默用标准名 |
| 台账/roster 唯一命中 | 静默用标准名 |
| 台账多个候选 | 问用户，并列候选 |
| 台账查无且疑似当周新签 | 问用户确认是否新签及合同号 |
| 金额与台账差异超过 10% | 问用户采用哪个口径 |
| 人名近音、roster 也定不了 | 问用户 |
| 普通词改动可能改变责任、进度或承诺 | 问用户 |

- 确证项静默改，正文**不写**"原文误 / 疑误听 / 〔注〕 / 待核实"。
- 未确证项汇成 **1 次** `AskUserQuestion`（每项给 2–4 个候选 + "其他"，项目候选尽量带编号或金额线索）。
- 用户答完：能定的填进正文；仍定不了的按用户口径写或暂不写（询问时一并确认）。
- **绝不**在纪要里用"待核实 / 疑误听"这类提示——用户要的是干净纪要。

## 四、台账检索脚本

```bash
# 自动定位最新台账并检索（无台账时手工 --file 指定）
python scripts/lookup_table.py --root <项目根> --find
python scripts/lookup_table.py --root <项目根> 百林 422 奥星 --json
python scripts/lookup_table.py --file <指定xlsx> 奥星
```

> `lookup_table.py` 为示例：
> 台账文件通配 `*验收*回款*明细表*.xlsx`，搜索 `26年计划验收明细表/财务数据/回款明细` 三张表。
> 其他项目按各自台账文件名、表名、编号格式改造后复用；编号格式差异只改 `classify()` 的拼号规则。
> 数字 query 只匹配"唯一编号"列；名称 query 匹配"客户名称/项目名称/摘要"列；按核心客户名去重判定唯一命中。

## 五、回写（让 skill 越用越准）

- 本次新确认的"误听→标准名"映射 → 追加进客户 `术语表.md` / auto-memory 别名表。
- 普通错字仅在用户确认后按 §2.5 回写混淆集；**未确认候选不得沉淀**。
- 下次自动命中，少问一次。

## 六、已确认映射示例（格式参考）

```

- 华西/华康 → 浙江华康
```
