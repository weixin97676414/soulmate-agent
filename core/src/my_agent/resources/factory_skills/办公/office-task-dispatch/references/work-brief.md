# 工作简报与周报/月报聚合


## 适用场景

- 月度/阶段工作简报：把某客户一段时间内的多场会议/工作切片聚合成正式信函式简报 docx。
- 触发："出 X 月简报 / 给甲方 X 写月度简报 / 月底整理一下 / 工作简报 / 工作总结 / 周报 / 月报 / 周报月报"。
- 通用周报/日报（非客户咨询场景）：套用 `assets/office-task-dispatch/templates/weekly-report-template.md` 骨架归纳填充。

## 步骤

1. **一次性确认 4 参数**：客户代号（必填，查不到走客户登记）、时间窗（默认本月）、抬头对象（默认读客户 README §1.2）、版本（外发版 / 内部留档版）；通用周报确认周期与素材来源。
2. **扫描 + 聚类**：`glob memory/projects/clients/{客户}/*/{YYYY-MM-*.md}`（8 类工作目录），按切片 frontmatter `工作主题`（或 `工作类型`）归并成 3–7 个主题块；主题数 >7 让用户选保留哪些。**主题清单先给用户审一次**再进下一步。
3. **拉日程（三层路线，优先序）**：企微 CalDAV → gcal MCP → ICS 离线 → 跳过。同日同主题以切片日志为准（含决议/行动项）；切片没记录的日程标 `[来源:{caldav/gcal/ics}]` 补入；三条路线都不可用则跳过，不报错。
4. **填每个主题块**（按简报模板）：主题概述、子事项标题（动名词）、日志条目（严格"{月}月{日}日，{动词}{对象}"格式）、备注/建议、相关文件。
5. **完成情况对照 + 下月计划**：读上月简报"本月计划"对照本月切片已完成行动项 → 三列对照表，状态四态图标 ✅已完成 / 🔄进行中 / ⏸暂缓（附原因）/ ❌未启动（附风险）；下月计划取 deadline 在下月窗口的待办，保守原则（少胜于错）。
6. **二次事实校对（强制）**：日期-动作回溯抽样、文件名实存（《XXX》grep outputs/）、承诺一致性（对照上月"下月计划"）、称谓核对、函号校对（对照客户 README 流水表）；任一失败加红色【二次校对未过】+ 违规清单。
7. **附件区自动汇总**：`deliverable_mining.scan_deliverables()` 出 3 桶（主交付物 / 中间产出物 / 待分桶）。
8. **人审（强制）**：简报草稿先以 markdown + diff 报告交用户审，**用户明确"OK 出 docx"才生成**；输出简报 docx + 归档 `_briefs/{年}-{月}.md`（供下月做完成情况对照）。

## 输入输出

- 输入：客户代号 + 时间窗 + 多份工作切片 + 上月简报归档 + 日程来源（CalDAV/gcal/ICS）。
- 输出：`outputs/{客户}/{客户}-{年}年{月}月辅导简报.docx`（信函式样：正文仿宋 14pt、标题黑体 16/15pt，含函号、寒暄、节序）+ 归档 markdown。

## 注意事项

- 简报排版与会议纪要不同：正文仿宋 14pt，大标题黑体 16pt、一级标题 15pt；页边距上 2.5 / 下 3.0 / 左 3.9 / 右 3.2 cm。
- 节序固定为 一、X月辅导工作 ⇒ 三、X月计划完成情况 ⇒ 四、次月工作计划（**跳过"二、"**）；函号、抬头对象、寒暄称谓、联系人、落款日期按客户 README 的"简报签发参数"段填。
- 人审门不可跳过；称谓与函号必须与客户 README 登记一致。
- 真名、精确金额、未公开战略按客户保密规则脱敏。

## 可复用示例

- 「出 6 月简报」→ 4 参数（客户 / 6 月 / 默认抬头 / 外发）→ 聚类并用户审主题 → 拉日程 → 填块 → 完成情况对照 + 下月计划 → 二次校对 → 附件汇总 → 人审 → docx。
- 「这周的周报帮我整理下」+ 素材 → 套 `weekly-report-template.md` 骨架归纳并填充（日报可只保留一、二两部分）。

## 支撑文件

- 简报总-分结构按简报骨架填充；客户侧另行维护代号与 README；交付物挖掘按交付物挖掘规则执行。
- 模板：`assets/office-task-dispatch/templates/weekly-report-template.md`。
