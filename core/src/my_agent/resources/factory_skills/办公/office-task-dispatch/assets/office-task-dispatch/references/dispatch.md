# 场景分流与执行细则 (Dispatch)

本文件是调度中心的**路由表与总纲**：负责"识别什么场景、走哪条路、按什么原则执行"。每个场景的具体操作步骤已按域拆分到三个分域文件，识别后按需加载，避免一次性读入全部 25 条工作流。

| 分域文件 | 覆盖范围 | 何时加载 |
|---|---|---|
| `dispatch-a-content.md` | §1 会议纪要、§2 文档总结、§3 邮件、§4 晨间简报、§5 知识库、§6 转 PPT、§7 客户跟进、§8 培训笔记、§17 周报日报 | 命中内容创作类场景时 |
| `dispatch-b-data.md` | §9 行动项追踪、§10 财务 ERP、§11 可接入办公软件、§12 数据分析、§13 OCR、§15 发票入账、§18 表格处理 | 命中数据/票据/表格类场景时 |
| `dispatch-c-special.md` | §14 合同审查、§16 录音转写、§19 翻译、§20 招聘 HR、§21 日程排期、§22 合同起草、§23 新媒体文案、§24 流程图、§25 OKR 绩效 | 命中专业服务类场景时 |

典型场景完整输入/输出示例见 `references/examples.md`，快速能力边界清单见 `references/capability-list.md`。

**全局约束**：全部 25 条工作流（与 `capability-list.md` 的 25 个能力场景一一对应）强制遵循 `references/fact_discipline.md`（事实纪律与可信度规范）——所有产出须标注置信度与来源、禁止臆造、不确定明说、被纠正立即改。

**异常处理统一模板**（所有场景通用）：
- **外部依赖缺失**（未装技能 / 未授权连接器）→ 明确说出缺失项 → 给 1 个内置降级方案（纯文本/本地文件/导出处理） → 给 1 个可选增强路径（安装/授权什么）。
- **输入格式不对 / 文件损坏 / 无法解析** → 明确告知问题 → 给 2-3 个修正选项（换格式、粘贴文字、分块上传）。
- **输出不满足需求** → 先问"具体哪部分不满意" → 给 3 个常见调整方向（更详细/更简短/换个视角/聚焦某子项）。
- **禁止话术**："可能吧""试试看""你自己处理一下"等模糊表达一律替换为可执行的下一步。

## 任务路由与成本控制（2026 新增原则）

办公智能体的真实瓶颈已从"能不能做"转向"任务链路变长后 token 与耗时是否可控"。本技能作为调度中枢，按下述规则路由，**只加载用得上的东西**：

1. **先判复杂度，再决定加载范围**：纯文本场景（纪要、邮件、文案、翻译、总结、OKR）走内置轻工作流，**不加载**文件处理类技能与分域文件；文件级场景（Excel/PPT/Word/PDF/图片）才调 `xlsx`/`pptx`/`docx`/`pdf`。
2. **分域文件按需加载**：命中哪个域，只读对应分域文件，不一次性读入全部 25 条工作流。
3. **单次只解决一个主场景**：用户一句话串多个场景时（如"纪要+行动项+邮件+周报"），按主场景优先，完成后询问是否继续下一个，不一次性铺开全部产出。
4. **大文件先探后处**：单文件 ≥ 50MB 或表格行数 > 5 万时，先读结构（表头 + 前若干行）确认口径，再决定全量或分块，避免无效全量解析。
5. **产出够用即止**：默认给一版完整产出 + 精简备选，不无限展开变体；用户要更多再补。

## AI 生成合成内容标识合规（强制，2026-09-01 起）

依据《人工智能生成合成内容标识办法》及**强制性国家标准《网络安全技术 人工智能生成合成内容标识方法》**（2026-09-01 施行），凡本技能产出**面向公众发布**的内容，交付时必须提示标识义务：

| 产出类型 | 显式标识（给人看） | 隐式标识（给机器查） |
|---|---|---|
| 新媒体文案 / 图文（§23） | 文首或文末显著位置标注"AI 辅助创作"等可识别提示 | 文件元数据写入生成属性、服务提供者、内容编号 |
| 图片 / 流程图 / 架构图（§24） | 显著角标或画面提示 | 元数据写入生成属性 |
| 音视频脚本 / 配音（§23） | 画面提示或语音/节奏提示 | 元数据写入生成属性 |
| PPT / 汇报材料（§6） | 首页或末页注明含 AI 生成内容 | 文件元数据写入生成属性 |

**执行要求**：
- **只打话题标签不够**——2026-05 已出现仅用 `#AI#` 被判定未履行标识义务并被处罚的案例。必须是文字或角标形式的明确提示。
- 对内使用（内部纪要、内部报表、内部对账）**不强制**标识；一旦对外发布或公开传播，必须提示用户完成标识。
- 涉及**数字人/换脸换声/虚拟场景**时，额外提示肖像权与授权风险。
- 广告/营销类内容同时叠加《广告法》自查：不夸大、不虚假宣传、数据标来源、特殊行业提示资质要求。

## 落地原则

### 一、通用工程原则
- 80/20：先啃最高频、最低价值任务，不追求一次性全自动。
- 先标准化后自动化：理清结构、统一口径再生成。
- 文件级场景（PPT / Word / Excel / PDF）由宿主文件处理能力完成，不重写。
- 财务场景口径必须对齐用户 ERP 的科目表与会计期间，禁止臆造科目或金额。
- 接入型办公软件可选调 宿主 内置连接器；已授权时直接拉取，未授权时降级导出处理，不伪造接口。
- 默认简体中文；中国股市相关遵循红涨绿跌。

### 二、组织级落地：可认证 · 可访问 · 可审计

企业级办公智能体的三条硬性要求是**可认证、可访问、可审计**，全流程数据来源白盒可追溯。本技能以既有机制对应，不新增负担：

- **可认证**：输出标注生成主体与依据来源（`[来源: ...]`），不冒用个人或机构名义。
- **可访问**：核心场景零依赖、降级路径明确，未授权连接器时也能产出结果，不卡死。
- **可审计**：关键结论逐条标置信度（已确认/推断/待确认），保留修改痕迹，错误公开标【已修正】；对外产出提示 AI 标识义务。
- **打通三个断点**：信息断点（跨文档/跨平台统一口径）、反馈断点（被纠正即改并留痕）、经验断点（用户同意后沉淀进知识库，见 A §5）。

### 三、Office 引擎与运行稳定性
- **四引擎智能识别（输出层）**：生成/编辑 Office 文件时按已安装环境选择引擎——① 已装 WPS：优先 WPS 兼容格式；② 已装 MS Office：输出 Office Open XML；③ 已装 LibreOffice：可经 headless 转换/校验；④ 以上皆无：纯 Python 库（python-docx/openpyxl/python-pptx）兜底。本技能默认走第 4 种（跨平台最稳），仅在用户明确有某引擎需求时切换；输出一律用 WPS/MS 通用的 OOXML。
- **自动重试**：调用外部命令/连接器/转换失败时自动重试最多 3 次，间隔递增（1s→3s→5s），3 次后仍失败再向用户报错，不静默丢弃。
- **硬件自适应**：处理大文件/大批量时检测 CPU 核数与可用内存，动态调整超时（默认 60s，大文件 120s+）与并发；内存不足时降级为分块处理，不 OOM 崩溃。
- **文件大小限制**：单文件 < 50MB 直接处理；≥ 50MB 建议先分片/精简，或说明"将分块读取、分批产出"。
- **失败可恢复**：长任务中途失败需能断点续跑或从最近检查点恢复。
