# 活动 H5 页面策划与前端交付

## 适用场景

- 用户给出一/多张活动页截图或设计预览，想据此生成**新的**活动。
- 想把活动参考变成方案（proposal）、页面架构（architecture）或 H5/Web 高保真前端草稿代码。
- 需要固定技术栈的活动页交接物。
- 触发词：参考活动页出 H5 方案、根据参考图做玩法抽象、按参考输出 HTML+CSS+JS、活动页策划与代码。

**不适用**：与活动页无关的请求；只要原始 OCR；要求导出精确锁定设计；要生产级后端逻辑或参考图里看不到的隐藏业务规则；要固定目标以外的技术栈。

## 固定平台与技术栈

- 平台：**H5 / Web**
- 栈：**HTML + CSS + JavaScript**
- 不要输出其他技术栈的代码。

## 模式

一个技能多模式，按用户意图选择：

| 模式 | 何时用 | 返回 |
|---|---|---|
| `analysis` | 想理解参考 | 观察到的 UI 结构、可见文本、玩法线索、用户流程线索、不确定项 |
| `proposal` | 想从参考得到新活动创意 | 参考摘要、玩法抽象、新活动概念、目标用户、目标、奖励与参与路径、反抄袭说明、视觉方向（更像运营活动 deck 而非普通备忘录） |
| `architecture` | 要实施规划不要完整代码 | 页面模块清单、模块顺序、弹窗系统、状态流、埋点建议、交付 schema |
| `delivery` | 要固定栈代码 | 文件结构、`index.html`、`styles.css`、`main.js`、`mock-data.js`、视觉提取摘要、实现说明 |
| `full` | 要完整流程 | 1 参考分析 → 2 玩法抽象 → 3 新活动提案 → 4 页面架构 → 5 交付 schema → 6 视觉方向 → 7 高保真前端代码 |

**默认模式规则**：未指定时——要新活动创意默认 `proposal`；明确要代码默认 `delivery`；两者都要默认 `full`。
`delivery`/`full` 下，若 brief 暗示海报式人物主视觉、页面会过长，默认**女性主导、可上线、tab 优先**的 H5 前端草稿。

## 步骤

1. **区分观察/推断/假设**：`Observed`（参考直接可见）/ `Inferred`（基于常见活动模式的推测）/ `Assumed`（参考不完整时的填补）。文字模糊或状态隐藏要直说。
2. **玩法抽象 + 生成新活动**：不照抄参考，必须在四维中至少改动 2 维——活动主题 / 奖励设计 / 任务结构 / 模块顺序或核心交互；不要同时保留相同的 hero 结构、玩法循环、奖励链。参考只取**结构、交互模式、密度、活动节奏**，视觉风格仅在契合目标主题时继承。
3. **活动族选择**：转盘/拆红包/签到/刮刮卡/翻卡记忆/宝箱解锁/集卡合成/限时冲榜/答题挑战/混合。选 1 个主玩法 + 最多 2 个辅助玩法；玩法用 data/config 可编辑；暴露可配置参数（时长、机会次数、奖励节奏、里程碑数、动画预设、视觉预设）；页面壳可复用。
4. **页面架构**：H5 长度控制——模块 >5 个，或同页含任务列表+奖池+记录+长规则时，用 **tab 优先**布局：首屏只放 hero + 核心动作 + 1 个关键摘要模块，次要内容进固定 tab，仅渲染当前 tab，长规则/记录放弹窗/抽屉/折叠。
5. **交付文件**：
   - 默认文件集：`index.html`（结构+真实上线式文案）、`styles.css`（设计 token/背景氛围/CTA/弹窗/响应式）、`main.js`（列表渲染/事件/状态/弹窗/玩法触发/轻量视图态）、`mock-data.js`（活动 meta、任务、奖品、CTA、弹窗、活动配置、动画预设）。
   - 本地输出根：全部最终文件放当前执行环境的 `project/<delivery-slug>/`；先建 `project/`，再建 `project/<delivery-slug>/`、`project/<delivery-slug>/image/`；`delivery-slug` 取自 `campaignMeta.id` 或净化的活动标题或稳定回退 `campaign-delivery`；不要把文件散落在工作区根/临时目录/裸 `project/` 下。
   - 各模式 Markdown 产物：`campaign-analysis.md` / `campaign-proposal.md` / `campaign-architecture.md` / `campaign-full.md`（本地写文件时）。
6. **顶部视觉资产生成**：当 brief/参考/用户措辞明确暗示海报式首屏、女性主导 hero、生成式首屏或图片优先活动页时，置 `need_image = true`，在写前端文件前**调用宿主图像生成工具**生成一张原创 hero 图（成人女性、写实商业海报风、主题匹配服饰/配色/道具/氛围；不要复制参考中的人物脸/姿势/构图，不要嵌奖品表/任务卡/页面文案/整屏布局）。代码指向 `./image/bg.png`；若宿主只输出 `image.png` 等平铺文件，转存为 `./image/bg.png`。默认每次运行重新生成（`regenerate_each_run`），除非用户明确要求复用。图片工具不可用/失败时**明确报告被阻塞并停止**，不要降级成占位图、纯渐变色或空图位。
7. **动画编排**：至少 1 个与主玩法绑定的标志性交互动画 + 2 个氛围/反馈动效层；优先 transform/opacity；提供 `prefers-reduced-motion` 降级。玩法默认动效：转盘加减速/指针回弹/中奖扇区发光；拆红包开裂/金币迸发/金额滚动；签到盖章/日历翻页/连击光柱；通用奖励翻卡/开箱/丝带扫过/数字滚动。
8. **交付 schema** 覆盖活动配置 + 页面交付契约，典型段：`campaignMeta`、`hero`、`activityFactory`、`activityConfig`、`tasks`、`rewards`、`lottery`、`modules`、`popups`、`animationSystem`、`visualPreset`、`assetOutput`、`stateMachine`、`tracking`。

## 输入输出

- 输入：1+ 张活动参考截图/设计预览；目标活动主题、用户、目标、平台（默认 H5）；模式（可选）。
- 输出：按模式返回分析/提案/架构/代码/full；本地交付物在 `project/<delivery-slug>/`。

## 注意事项（硬约束）

- 只用 H5/Web + HTML/CSS/JS；**不编造后端接口**、不假装模糊文字精确、不声称模糊图能像素级还原。
- **禁止可执行本地写文件命令**；用户明确要本地文件且宿主支持本地执行时，用 Python 直接生成产物，而不是只回文件结构或代码块；生成成功要汇报实际路径。
- 高保真草稿（非低保真线框）：写码前先提取 4–8 条视觉语言要点（配色对比/hero 构图/装饰密度/卡片面板处理/CTA 样式/图标徽章样式/弹窗调性/整体氛围词）。视觉决策优先级：显式用户 brief 与目标主题 > 目标节日/季节/品牌调性 > 参考布局与交互线索 > 参考配色与装饰。
- 上线级前端质量：首屏视觉完整、模块内部有代表性内容（空容器不可）、真实 mock 文案、覆盖 active/selected/disabled/claimed/exhausted/popup-open/tab-selected 等状态、移动端响应式与触控目标。**这是接近上线的前端完成度，不是接后端的生产部署。**
- 避免默认反模式：Arial+灰底+白圆角卡、重复空 `.section-card`、hero 只有一行 `<h1>`/`<p>`、无层级按钮、线框感、人物型 brief 用纯文字 hero 或占位图位、声称用了生成图但本轮没调图像工具、生图复刻参考同一张脸/姿势、长页默认纵向堆叠全部模块、把 tab 当装饰、Python 本地交付漏建目录或漏存 `bg.png`。
- 用生成 hero 时给明文交接提示（例）："需要把生成好的图片，改名为 bg，图片类型为 png，放到 project/&lt;delivery-slug&gt;/image 目录下"。

## 可复用示例

- "参考这几个活动页，给我出一个新的 H5 活动方案。" → `proposal`
- "根据这个参考图，先做玩法抽象，再给我页面架构。" → `architecture`（或 full 前半）
- "按这个活动参考，输出 HTML + CSS + JS 版本。" → `delivery`
- "我想同时要策划和代码，你走 full mode。" → `full`
