# 面试评估与追问（回答 → 评分 → 红绿灯）

## 适用场景

- 候选人面试结束，要把回答转成结构化评估
- 需要判断候选人是「真做过」还是「只会说」
- 需要给出各维度评分与推荐结论

## 步骤

1. **收集回答原话**：只用原始回答，不接受「他说得还行」这类转述；有疑点当场追问原话。
2. **按维度评分（1–5 分）**：

   | 维度 | 评价标准 |
   |---|---|
   | 岗位理解 | 对岗位的理解深度 |
   | 问题解决 | 回答的逻辑性与可行性 |
   | 经验迁移 | 能力迁移到新岗位的潜力 |
   | 团队管理 | 管理理念与案例 |
   | 文化匹配 | 价值观与动机 |
   | ATS 合规 | 简历是否 ATS 友好 |

3. **追问深度评估（红绿灯）**：

   | 信号 | 说明 |
   |---|---|
   | 🟢 绿灯 | 能 6 层深回答、PEARL 清晰、有失败反思 |
   | 🔴 红灯 | 只说漂亮话、回避失败、表面深入 |

   逐项勾：能 6 层深回答吗 ✅/❌；PEARL 清晰吗 ✅/❌；有失败反思吗 ✅/❌。
4. **回答质量打分（快捷标尺）**：
   - 优秀 4–5 分：STAR 结构清晰、量化数据、考虑过多种方案、有反思、诚实（不会的不装会）
   - 合格 2–3 分：基本完整但缺细节、数据不量化、说不清「为什么」、缺反思
   - 差 0–1 分：答非所问、过于笼统、明显夸大造假、答不出硬撑
5. **区分表现 vs 实质**：检查候选人所说的「三大亮点」是否真的成立，表达结构化不等于有深度。
6. **输出评估报告**：核心亮点 / 风险预警（红绿灯）/ 各维度评分 / 追问深度评估 / 综合评分（X/5）/ 推荐结论（推荐 / 谨慎推荐 / 不推荐 + 理由）。

## 输入输出

- 输入：面试回答原话（线上 / 线下）+ 对应岗位与简历
- 输出：面试评估报告（各维度评分 + 红绿灯 + 综合评分 + 推荐结论）

## 注意事项

- 评估看实质：口才好 ≠ 能力强；避免确认偏误，亮点与疑点都要有证据。
- 回答质量好 ≠ 层级高：说得好但没做过，降一级并标注「认知到位」（配合 `assets/agf-analysis-logic.md`）。
- 人格类疑点（说谎 / 推责 / 归因外部）单次事件按「状态」记录，不定性；同类 ≥2 次才升级。
- 评估只给结论与证据，不替使用者做最终人事决策。

## 可复用示例

```
【张三】面试评估报告
一、核心亮点：能完整复盘订单重构，量化 QPS 从 1k→5k
二、风险预警：🟢 有失败反思；🔴 「团队协作」回答笼统，追问后仍无具体案例
三、各维度评分：岗位理解 4 / 问题解决 4 / 经验迁移 3 / 团队管理 3 / 文化匹配 3 / ATS 4
四、追问深度：6 层深 ✅ / PEARL ✅ / 失败反思 ✅
五、综合评分：3.8 / 5
六、结论：谨慎推荐（建议下一轮补验团队协作，用行为问题追问具体场景）
```
