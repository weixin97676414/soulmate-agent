# 批量文件夹筛选与报告

## 适用场景

- 一个岗位有一批简历（PDF / DOC / DOCX / HTML / TXT）要一起筛选排序
- 需要按 JD 自动评分并输出可点击展开的 HTML 报告或 Markdown 报告
- 面试官有固定风格偏好，希望面试问题更贴合本人关注点

## 步骤

1. **确认职位文件夹结构**：
   ```
   jobs/
   ├── 后端开发-3年经验/        # 职位文件夹（命名：职位名称-级别）
   │   ├── JD.txt              # 职位描述（必需）
   │   ├── 候选人A.pdf
   │   ├── 候选人B.docx
   │   └── 候选人C.pdf
   ├── 产品经理-资深/
   │   ├── JD.txt
   │   └── ...
   └── personalprefer.txt      # 面试官偏好配置（可选，全局共享）
   ```
2. **读取并解析 JD.txt**：从 `assets/JD-template.md` 推荐结构出发，拆出硬性要求 / 核心技能 / 软性素质 / 加分项 / 业务领域。
3. **批量解析简历**：支持 PDF、DOC、DOCX、HTML、TXT；**无需结构化命名**，从内容中提取姓名与信息。
4. **匹配度评分（口径复用）**：打分权重、封顶规则与分档一律复用 [hr-jd-matching](references/hr-jd-matching.md) 的严格口径，本文件只负责批量执行与报告产出，不另立权重或分档；硬性要求不满足的候选人直接淘汰。
5. **生成面试报告**：每个候选人给「匹配点总结 / 风险点待确认 / 定制化面试问题清单」。问题分 A 技术能力（3–5 题）、B 项目深挖 STAR（2–3 题）、C 软实力（2–3 题）、D 待确认事项（1–2 题）；题型的期望回答要点见 `assets/interview-questions-framework.md`。
6. **个性化**：若 `jobs/personalprefer.txt` 存在（模板见 `assets/personalprefer-template.txt`），据面试官性格、偏好风格与基础素质要求调整问题与考察权重。
7. **输出报告**：
   - 本地 HTML 报告（推荐）：`职位文件夹/面试报告-YYYY-MM-DD.html`，含可点击展开的排序表、匹配分析、可打印问题清单。
   - 或 Markdown 报告：`职位文件夹/面试报告-YYYY-MM-DD.md`。

## 输入输出

- 输入：职位文件夹（JD.txt 必需、简历文件必需、personalprefer.txt 可选）
- 输出：候选人排序报告（HTML 或 Markdown），保存在对应职位文件夹内

## 注意事项

- **JD.txt** 放在各职位文件夹内，随岗位变化；**personalprefer.txt** 放在 `jobs/` 根目录，全局共享，不随岗位变化。
- 报告字段：排名 / 候选人 / 匹配度 / 推荐等级 / 核心匹配点（3–5 条）/ 主要疑虑（2–3 条）/ 建议面试时长 / 面试问题清单。
- 岗位特殊偏好（大厂背景、创业经验）、团队技术栈、急招程度会影响评分宽松度——使用者提供后据此调整。
- 所有简历在本地处理，不上传外部服务；报告保存在本地职位文件夹。
- 与 [hr-interview-design](references/hr-interview-design.md) 的分工：本文件负责「批量 + 报告产出」，深挖题设计与追问技巧以后者为准。
- 与 [hr-jd-matching](references/hr-jd-matching.md) 的分工：打分口径与权重由后者唯一定义，本文件只调用不重定义。

## 可复用示例

```
使用者：帮我筛选 jobs/后端开发-3年经验 这个职位的简历
→ 读取 JD.txt → 解析文件夹内所有简历 → 评分排序 → 生成 面试报告-2026-03-05.html

使用者：帮我准备 jobs/产品经理-资深/张三.pdf 的面试问题
→ 读取该职位 JD → 只针对这份简历生成详细面试清单

使用者：JD 改了，重新筛选 jobs/算法工程师 的简历
→ 重新读取更新后的 JD.txt → 重新评分排序
```
