# 录用决策与转正画像闭环


## 适用场景

- 走完筛选 + 面试，要给候选人最终推荐结论
- 需要在前几轮结果之上做综合决策
- 候选人入职转正，要把简历分析结论迁移成员工画像基线

## 步骤

### 一、最终推荐（决策矩阵）

| 简历筛选 | ATS 分数 | 追问深度 | 面试评估 | 最终结论 |
|---|---|---|---|---|
| 9.0+ | 80+ | 高 | 5/5 | 强烈推荐 ✅ |
| 8.5+ | 75+ | 中 | 4.5/5 | 推荐 ✅ |
| 7.5+ | 70+ | 低 | 4/5 | 谨慎推荐 ⚠️ |
| <5.5 | <60 | 无 | <3.5/5 | 不推荐 ❌ |

1. 汇总 [hr-jd-matching](hr-jd-matching.md)（简历筛选分 / ATS）、[hr-interview-evaluation](hr-interview-evaluation.md)（追问深度 / 面试评估）。
2. 出「面否 / 可面 / 倾向录用」三档 + 理由（命中 Job Card 否决项 → 直接面否）。
3. 给**风险控制清单**：入职前学历核验、简历经历逐段复核、试用期观察点。
4. 不替使用者做人事决策——给证据、给选项、给验证方式。

### 二、归档

- 收简历即建档 `resumes/{姓名}-简历分析-{年份}.md`，线上 / 线下各阶段即时回填。
- 简历原件一并归档；多候选人对比表仅在使用者明确要求时做，不主动做。

### 三、转正闭环：简历 → 画像（手动触发 + 确认）

1. **触发**：员工转正，使用者说「转正」「建画像」「转员工画像」。
2. AI 展示要写入画像的基线信息（信号层结论 / 风险项 / 待验证维度），**等使用者确认**。
3. 确认后：
   - 按 `assets/profile-baseline-template.md` 建「基线画像」，标注待验证
4. 简历分析档案保留不删（候选历史），画像与档案并存。

## 输入输出

- 输入：简历筛选分 / ATS 分、面试评估结果、Job Card、面试与背调补充观察
- 输出：最终推荐结论 + 风险控制清单；转正时输出员工画像基线

## 注意事项

- 决策矩阵是汇总参考，不是硬性公式；任一维有硬否决立即降档。
- **迁移的是结论**（层级预判 / 风险项 / 验证点），不是复制整份简历。
- 简历信号层置信度 ≤55%，正式 AGM 答题数据出来后裁决修正（简历可能高估，如简历判 L3、答题判 L2）。
- **手动触发 + 确认**：不自动写画像；未答题也可先建「基线画像」，不阻塞。
- 简历分析档案永不删除，是候选历史 + 画像信号层来源。
- 不读他人画像做对比——候选人是外部人，除非使用者明确要求。

## 可复用示例

```
汇总：简历筛选 8.6 / ATS 78 / 追问深度 中 / 面试评估 4.3
→ 决策矩阵 → 推荐 ✅；风险控制：入职前学历核验 + 试用期观察「团队协作」信号

转正：
使用者：「张三转正了，帮我建画像」
→ AI 展示基线：层级预判 L1.3（置信度 ≤55%）/ 风险项「协作待验证」/ 待验证维度 …
→ 使用者确认 → 按 profile-baseline-template 落盘「基线画像」
→ resumes/张三-简历分析-2026.md 保留
```
