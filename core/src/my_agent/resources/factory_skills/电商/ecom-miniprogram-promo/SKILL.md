# 小程序每日推广文案生成（公众号 + 小红书）

配套脚本：`scripts/select_item.js`。
本技能不绑定具体小程序：把内容文档（content.js / content.json）放进工作区即可每日产出双平台文案。

## 适用场景

- 每日自动选一条内容，生成公众号文章版 + 小红书笔记版两套推广文案，吸引用户打开小程序。
- 触发词：每日生成小程序推广文章、小程序种草、每天发文章、跑小程序推广。
- 输入：小程序内容源 `content.js` / `content.json`。

## 步骤

1. **准备数据（标准格式，同时兼容任意结构）**：
   ```js
   // content.js
   module.exports = {
     APP: { name:"小程序名", slogan:"一句话定位", audience:"目标人群", platforms:["公众号","小红书"] },
     ITEMS: [ { id:"item-001", title:"标题", summary:"摘要", content:"正文",
                images:["https://.../a.jpg"], cover:"https://.../a.jpg",
                tags:["标签"], category:"guide" } ]
   };
   ```
   - 自动探测兜底：非标准字段名（`name` 代 `title`、`gallery` 代 `images`）会自动识别；识别不到则把整条原始数据交给创作环节提炼，不报错。
   - 避坑/种草判定：优先看 `category`（含 pit/fall/坑/避坑/fake 记为避坑）；无 category 时扫描"不适合/谨慎/危险/排雷"等负向词自动判定。
2. **运行选取脚本**：
   ```bash
   node scripts/select_item.js <workspace>/content.js <workspace>/.covered.json
   ```
   - `status=OK`：含 `facts`（app、needsAppInfo、item{id,title,summary,content,images,cover,tags,category,isPitfall}、raw）。
   - `needsAppInfo=true`（无 APP 段）：先向用户询问小程序名称/定位/人群，再创作。
   - `status=NONE`：全部条目已写过 → 告知"内容已全覆盖，待更新文档后继续"，**结束，不产出文章**。
3. **创作两套文案**：按 `item.isPitfall` 选种草/避坑框架，依据 `facts`（含 `raw`）创作。
4. **写 4 个文件**（按当天日期）：
   - `promo-output/YYYY-MM-DD_小红书.md` / `.txt`
   - `promo-output/YYYY-MM-DD_公众号.md` / `.txt`
   - `.txt` 为去格式纯文本，便于直接粘贴发布。
5. 交付这 4 个文件。

## 选取策略（脚本已实现）

- 每日只写 1 条，按文档顺序轮转完。
- 每 3 次运行穿插 1 篇"避坑/反差"内容。
- 维护 `.covered.json` 去重，永不重复；文档新增条目自动进入未覆盖池。

## 创作要点

**小红书版（爆款强化）**：标题"颠覆认知+情绪词+利益点前置"，用封神/真香/后悔没早知道/天花板/0元/绝了等强词，核心词放最前，≤20 字；开头 3 秒钩子（"谁懂啊…""别再去 XX 了"）；正文 emoji 分段、关键信息加粗、口语化；"注意事项"写成"划重点"；结尾强互动 + 收藏钩子 + CTA；话题标签 5-8 个含 `#{{appName}}` 与品类/地域词。
- 种草型骨架：标题利益钩子 → 情绪开场 → 📍地点/分类 → 🔥真香点(2-3) → ⚠️划重点 → 📷小程序实拍图 → 人群适配 → 互动+收藏 → 标签 → 引导打开小程序。
- 避坑型骨架：🚨"千万别去！多少人被坑" → 真相 → ⚠️划重点 → ✅用「{{appName}}」查靠谱的 → 互动+收藏 → 标签。

**公众号版（爆款强化）**：标题 0.5-2 秒定生死，用反差/反常识/数字，核心信息放前 15 字，禁止最/第一/顶级；开头黄金三秒抛利益或冲突；正文"是什么→为什么→怎么办"，短段落 ≤5 行，小标题用反差短语，重点加粗；结尾人格化观点 + 金句 + 引导「在看」/转发/打开小程序。

**通用规则**：行业词随 `raw` 实际领域自适应（美食/景点/穿搭/好物各用其词），**不套固定行业词**；所有事实必须来自 `facts`/`raw`，字段为空时如实省略或写"（以小程序内为准）"，**不得编造数据**。

## 配图规范（用文档真实图，零积分）

- 来源：`facts.item.images` + `facts.item.cover`，**不调用任何图像生成工具**。
- `.md` 版：文末嵌入前 3 张 `![图](src)` + 一行"更多实拍见「{{appName}}」小程序内共 {{images.length}} 张"。
- `.txt` 版：列"📷 配图（直接用这几张）："+ 每行一个 URL（全部 images）。
- 优先用 `cover` 作首图；文案中"N 张用户实拍"须与 `images.length` 一致；图片多为第三方外链，发布前建议自行下载/转存。

## 注意事项

- 合规底线：不涉政、不造谣、不色情低俗违法；不用平台违禁绝对化词（最/第一/顶级/根治）。放开的是情绪与钩子，不是底线。
- 本技能调性独立设定，不沿用其他任务的禁用词规则。
- 若对某篇不满意可要求重跑当日：先用 `--dry` 预览，确认后正式跑（正式跑会消耗该条目配额）。
- 部署：把技能目录放到自己的 skills 目录，导出 `content.js` 放工作区，对 Agent 说"跑小程序推广"；可选设每天定时运行。
