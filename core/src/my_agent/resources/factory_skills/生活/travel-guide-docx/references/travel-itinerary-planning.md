# 行程规划设计（精确到小时）


## 适用场景

用户消息出现任何旅行意图即触发，包括但不限于：
「旅行攻略」「行程安排」「旅游规划」「X日游」「出行计划」「去XX玩」「XX怎么安排」「旅行计划」「自由行」「亲子游」「情侣游」「毕业旅行」「周末去哪」「假期去哪」「推荐XX景点」「XX好玩吗」「我想去XX」「XX怎么玩」「带孩子去XX」「第一次去XX」「XX必打卡」「XX穷游」「XX旅游攻略」「小红书推荐XX」「国庆/五一/暑假/寒假去哪」。
即使用户只是随口提到一个地名并有外出意向，也应主动帮他规划。

本技能对国内城市覆盖最好（`scripts/spots_db.py` 内置 10 城：重庆 / 成都 / 西安 / 杭州 / 北京 / 上海 / 广州 / 深圳 / 武汉 / 南京）；其他城市用自定义坐标或纯文字攻略。

## 输入

**必填**（缺任一先问用户补全，再开始规划）：

| 参数 | 说明 |
|---|---|
| 目的地 | 旅行目的地城市/景区 |
| 出发地 | 出发城市 |
| 行程天数 | 旅行天数 |

可选：出行人数、预算范围、出行类型（亲子/情侣/独自/团队/毕业/银发）、节奏（轻松/适中/紧凑）、兴趣（美食/夜景打卡/自然风光/人文历史/网红取景）、日期。

## 步骤

### Step 1 · 收集偏好（必须问，别猜）

用提问工具一次问完，不要逐个问：

1. 预算档位（经济/舒适/品质，人均，不含大交通）
2. 同行人（独自/情侣/朋友/带家人——影响住宿摊薄和节奏）
3. 节奏（轻松/适中/紧凑——决定每天排几个点）
4. 兴趣（美食/夜景打卡/自然风光/人文历史/网红取景——决定行程骨架）
5. 日期（没定就帮用户建议：避开假期最高峰的前 1–2 天）

### Step 2 · 研究目的地（真实数据，禁止编造）

搜索经常不可用（超时/反爬），按降级链处理：

1. 先试 `web_search` / MCP 搜索
2. 搜不到 → 用领域知识生成，**时效信息（门票价格、预约政策）必须标注"出行前复核"**
3. 绝不编造精确价格当事实写——写"约 ¥130–140（以官方渠道为准）"

研究覆盖：核心景点清单、地理分布（决定分区）、交通方式、门票/预约、美食、住宿片区、注意事项。

搜索用词参考：
- `"[目的地] [X]日游 最佳路线"` → 主流行程结构
- `"[目的地] 必去景点 开放时间 门票"` → 景点基础信息
- `"[目的地] 美食推荐 具体店铺 地址 营业时间"` → 真实餐厅
- `"[具体景点/餐厅] 营业时间"` → 核实最新信息

**交通（禁止编造）**：用 `web_search` 搜真实车次，优先携程（`trains.ctrip.com`）或 12306；记录车次号、发车/到达时间、票价。

**可选增强：交通班次 + 具体住宿**（用户给了出发城市时做）：
- 高铁/航班：搜"`出发城市` 到 `目的地` 高铁/航班"（12306/航司/第三方票务页），取 2–3 个真实车次/航班填进 `plan.json` 的 `transport`
- 住宿：搜"`目的地` 推荐酒店 亲子/海景"或直接用领域知识，填 2–4 家**真实存在的酒店/民宿**（名称、片区、价位带、特点）到 `plan.json` 的 `stays`，预订渠道填"携程 / 美团 / 飞猪 / 去哪儿"
- **现实约束**：携程/12306/美团均无公开免费 MCP（需企业 key），不要承诺 MCP 集成；用搜索替代，所有价格标注"以平台实时为准"
- 查不到或超时 → 字段留空，骨架保留空表由 AI 兜底

### Step 3 · 行程设计（AI 唯一需要动脑的部分）

- **行程跟着地理走**：相近景点放同一天，画在地图上是同一个圈。这是攻略质量的核心
- **远郊单独一天**：离市区 >50km 的（如武隆、都江堰、兵马俑）单独一天，给出高铁/跟团方案对比
- **每天 3–4 个点**（适中节奏），别把行程排满
- **夜景放傍晚后**，夜景城市（重庆/西安/上海）每天至少一个夜景位
- **住宿只推荐一个片区，全程不换店**——除非行程跨城。给出 3–4 个片区对比表 + 节假日价格

**出行类型差异化：**
- **亲子**：宽松节奏 + 午休时间 + 儿童友好设施优先 + 避开暴晒时段
- **情侣**：加入浪漫元素（特色餐厅、日落观景、夜景打卡）
- **独自**：青旅/民宿、灵活节奏、注意安全提示
- **银发**：低强度路线、无障碍设施、就近医疗

### Step 4 · 精确到小时排程

**时间规划原则：**
- 景点开门前 15 分钟抵达，避开排队高峰
- 景点间预留 30–60 分钟交通时间
- 午餐避开 12:00–12:30 高峰（建议 11:30 或 12:30）
- 先安排精力要求高的项目，后安排轻松项目
- 返程日最晚活动须在出发前 2 小时结束

**每项活动必须包含：**
- ⏰ 精确时间段（如 09:00-11:30）
- 📍 店铺/景点名称 + 详细地址
- 营业/开放时间
- 费用（门票/人均消费）
- 推荐内容（菜品/游览动线/拍照点）

**行程自检清单：**
- [ ] 每项活动都有具体时间（几点几分）
- [ ] 景点有准确的开放/闭馆时间
- [ ] 餐厅有营业时间、人均消费、必点推荐
- [ ] 考虑了用餐高峰（避开 12:00-12:30）
- [ ] 两景点间预留足够交通时间，标注耗时与费用
- [ ] 开门前 15 分钟抵达、考虑最佳拍摄时间
- [ ] 合理安排体力（先难后易/先远后近），留有休息时间
- [ ] 返程/末班交通前有缓冲

## 输出

- `spots` 直接写景点名（取自 `scripts/spots_db.py`，坐标自动查）或用对象 `{"name":"自定义","lon":..,"lat":..,"desc":".."}` 写自定义标签

- 景点太密集挤在一起（planner 会报 unresolved）→ 用 `overview.merge` 合并标签名
- `transport` / `stays` 可选，Word 文档会自动预填对应章节（见 `travel-guide-docx.md`）

  - 地址：[省市区街道门牌号]

**Emoji 约定**：⏰ 时间点 / 📍 景点 / 🚶🚕🚌🚄✈️ 交通 / 🍜🍽️☕ 餐饮 / 🏨 住宿 / 🛍️ 购物 / ⚠️ 注意 / 📞 电话。

**质量红线**：每项活动有精确时间段、每家店有完整地址+营业时间+人均、交通数据来自真实数据源、景点有开放时间+门票、末尾注明数据来源 URL。含糊的"上午游玩"、只写"吃当地美食"、编造车次号/票价都是禁止项。

## 注意事项

- 票价和时间以实际购票/出行时查询为准，建议出发前再次确认；攻略末尾附免责声明和数据来源 URL。
- 时效信息（门票、预约政策）出行前 1–2 周复核官方渠道。
- 无公开免费的携程/12306/美团 MCP，不要向用户承诺此类集成。
- 搜索不可用时用领域知识兜底，但价格类信息一律写"约"并标注以官方为准。

## 可复用示例

- "深圳出发去梧州2天怎么安排" → 搜真实高铁 + 骑楼城 + 纸包鸡餐厅，输出精确时间表
- "带6岁孩子去广州长隆2天" → 亲子模式，宽松节奏，儿童票价，午休时间
- "国庆去成都玩3天" → 地理聚类（春熙路/宽窄巷子同区、大熊猫基地一天、远郊单独一天），产出 `plan.json` 供图与 Word 管线
- "情侣第一次去厦门3天" → 加入鼓浪屿日落、海边餐厅、网红打卡点
