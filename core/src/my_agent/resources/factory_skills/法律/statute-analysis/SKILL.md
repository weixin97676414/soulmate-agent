# 法条实务分析（体系定位 / 概念深挖 / 类案验证）

## 适用场景

- 用户想了解某法条在体系中的位置、上下游关联、竞合关系。
- 用户不懂法条中的模糊词（「合理期限」「重大误解」「明显不当」「重大」「明显」）。
- 用户担心 AI 的法条分析不符合司法实践，要求「类案检索」「验证分析」，或想知道法官的审查重点。

## 步骤

### 一、法条体系定位（legal-system-mapper）

以某法条为核心节点，构建关联网络：

1. 上位规范：上位原则条款是哪条？
2. 并列条款：同层级、解决类似问题但适用条件不同的条款有哪些，列表对比差异。
3. 下位细化：有哪些司法解释、指导性案例对该条作了细化？
4. 程序衔接：主张该条权利时举证责任如何分配、诉讼时效如何计算？
5. 竞合分析：可能与哪些条文产生请求权竞合，各自利弊？
6. 用思维导图的文字树形结构呈现以上关系。

输出：法条关联图（文字树）+ 并列条款对比表 + 竞合分析建议。

### 二、不确定概念深挖（legal-concept-deep-dive）

对法条中的不确定概念（输入法条编号+内容 + 待深挖的概念词，概念词通常来自上一步）：

1. 立法原意；2. 学理通说（内涵与外延）；3. 司法解释/指导意见细化；4. 裁判标准（列出判断要素清单）；5. 边界案例（「刚好构成」2 个 +「刚好不构成」2 个）；6. 常见误区。

输出：判断要素清单 + 正反边界案例 + 常见误区。

### 三、类案检索与验证（legal-case-validator）

针对某法条在司法实践中的适用：

1. 典型适用场景（最常见 3 类案件类型）；2. 裁判分歧（是否存在、分歧点与各方观点）；3. 指导性案例（最高法是否有、裁判要旨）；4. 高频败诉原因（≥3 个，具体）；5. 法官审查重点；6. 实务操作建议清单。

### 铁律（验证环节，必须遵守）

- **AI 生成的案例信息务必去数据库交叉验证**：中国裁判文书网、北大法宝、法信。
- AI 可能生成看起来真实但**根本不存在的案号与裁判要旨**——「逢案必验」是底线。
- 本流程提供分析框架，不能替代判例研究；真实案例必须由使用者在数据库中核实。
- 若找到裁判分歧，这本身就是庭前准备的重要方向。

## 输入输出

- 输入：法条编号（+ 条文内容）、待深挖的模糊概念词（可选）。
- 输出：体系关联图与对比表（定位）；判断要素清单与边界案例（深挖）；典型场景、裁判分歧、败诉原因、审查重点、实务建议（验证）。

## 注意事项

- 体系定位是避免「用错法条」的关键步骤；诉讼时效与举证责任是高频考点，必须涵盖。
- 不确定法律概念常是庭审交锋焦点，边界案例尤其重要。
- 本功能是验证环节，不是判例研究本身；必须提醒用户到权威数据库核实。
- 引用条文须核对现行有效性；AI 输出不得当作已核实的司法实践结论。

## 可复用示例

用户：「这个法条在实践中怎么用？会不会不符合司法实践？」
处理：先定位《民法典》第 X 条的上位/并列/竞合关系 → 对其中模糊概念列出判断要素与边界案例 → 给出典型案件类型、裁判分歧与高频败诉原因 → 明确要求用户到裁判文书网/北大法宝核实案号。

用户：「什么叫『重大误解』？和欺诈怎么区分？」
处理（以《民法典》第147条为例）：从立法原意、学理通说、司法解释切入 → 列出误解对象范围（意思表示本身 vs 动机）、与动机错误的区分标准、与欺诈的界限 → 正反各举 2 个边界案例 → 指出裁判中的高频争议点。
