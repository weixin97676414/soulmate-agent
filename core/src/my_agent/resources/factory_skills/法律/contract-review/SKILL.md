# 合同审查与风险识别

## 适用场景

- 用户上传或粘贴一份合同，要求「看看有没有坑 / 有没有风险 / 帮我审一下」。
- 用户针对单条条款提问：「这条违约责任公平吗」「这个管辖约定有效吗」。
- 需要对比两份合同版本的差异条款。
- 需要检查一份合同是否缺少必备条款。

## 步骤

1. **识别合同类型与基本信息**：判断合同类别（劳动 / 买卖 / 服务 / 租赁 / 合作 / 知识产权 / 金融投资等），提取当事人、标的、金额、期限、签订日期。合同文本不完整时先要求补齐。
2. **条款提取**：按类型分类提取关键条款并标注条款编号，便于引用：标的 / 价款 / 履行期限 / 违约责任 / 解除 / 争议解决 / 保密 / 知识产权。检查条款编号是否连续，识别缺失条款。
3. **四维审查**：
   - 合法性：是否违反法律强制性规定、公序良俗，是否存在无效条款。
   - 公平性：权利义务是否对等、违约责任是否合理、解除条件是否公平。
   - 完整性：必备条款是否齐全、约定是否明确具体。
   - 可操作性：履行方式、时间节点、违约责任是否可执行。
4. **风险分级**：每条风险给「高 / 中 / 低」级别，写明风险原因与修改方向，并引用法律依据（如《民法典》《劳动合同法》《民事诉讼法》相关条文）。
5. **输出结构化审查报告**，并给出修改建议。
6. **标注升级/转介情形**：标的额较大、合同复杂、涉及跨境/刑事/知识产权/股权/监管、接近时效、证据薄弱时，明确建议专业律师介入。

> 可执行实现（可选）：一次性完成条款提取 → 风险检测 → 合规检查 → 报告生成。

```bash
python3 scripts/hetong/contract_review.py --input <合同文本文件> --type <合同类型> --output <报告输出路径>
```

- 脚本依赖同目录的 `scripts/hetong/` 下模块（`clause_extraction.py`、`risk_detection.py`、`compliance_check.py`、`report_generator.py`）。
- 风险规则与法规数据来自 `assets/hetong-data/risk_rules.json`、`assets/hetong-data/legal_database.json`。
- 命令参数按脚本内自述整理，**未实测运行**；若报错以脚本实际输出为准。

## 输入输出

- 输入：合同全文或关键条款文本、合同类型（可缺省由系统判定）、审查侧重（如「只看违约责任」）。
- 输出：合同类型 + 总体判断 + 风险表格（条款 / 风险级别 / 问题 / 修改方向 / 法律依据）+ 缺失条款 + 综合评分 + 下一步建议 + 免责声明。

参考输出骨架：

```
【基本信息】合同类型 / 合同名称 / 风险等级
【风险总览】高/中/低风险条款数、缺失条款数
【风险清单】[高风险] 第X条 - 违约责任：问题 / 原文 / 风险 / 建议 / 依据
【缺失条款】逐条列出建议补充的条款
【综合评分】合法性 / 公平性 / 完整性 / 综合
【结论建议】是否建议修改后再签署
```

## 注意事项

- 始终坚持免责声明：审查意见仅供参考，不构成法律意见；重大合同建议咨询专业律师。
- 不得承诺案件或谈判结果；不得把不完整事实当成充分依据。
- 合同类型判断错误会导致规则失配，类型不确定时向用户确认。
- 不同地区规则存在差异，引用的法条须核对时效（是否已修订/废止）。
- 涉及格式条款、劳动法倾斜保护、管辖约定合法性时是高频风险点，优先看。

## 可复用示例

用户：「帮我看看这份软件技术服务合同有没有风险。」
处理：识别为服务合同 → 提取条款 → 重点检查违约责任对等性、管辖法院约定、付款与验收条款 → 输出：

```
【高风险】第7条 违约责任：仅约定甲方违约金30%，乙方违约责任不明确
  建议：明确乙方违约金比例或计算方式；依据《民法典》第585条
【高风险】第12条 争议解决：约定甲方所在地法院管辖，不利于乙方
  建议：改为合同履行地或原告所在地；依据《民事诉讼法》第34条
【缺失条款】知识产权归属 / 保密 / 不可抗力 / 合同解除 → 建议补充
【综合评分】合法性85 / 公平性60 / 完整性70 → 综合72
【结论】存在权责不对等，建议协商修改后再签署。
```

用户：「合同里违约金约定过高，能调吗？」
处理：引用《民法典》第585条说明违约金过高可请求调整的规则，并提示司法实践中「过分高于损失」的判断标准；提示需结合实际损失举证。
