| 存储与持久化 | 会话/消息往返（含 tool_calls）、事务回滚、损坏数据容错、**重启后仍在**、懒加载、数据库故障降级为内存模式 |


## 二、打包

```powershell
cd desktop

npm run build:core    # PyInstaller 打包 Python 核心 -> core/dist/agent-core/
npm run verify:core   # 在真实 exe 上验收核心
npm run dist          # 核心 + 前端 + electron-builder -> desktop/release/
npm run verify:app    # 在打包后的完整应用上验收集成（会短暂启动窗口）
```

需要精简版（无长期记忆）时：

```powershell
$env:AGENT_WITH_MEMORY="0"; npm run build:core
```

> `AGENT_WITH_MEMORY` 开启但环境里没装 chromadb 时**构建会直接失败**，
> 而不是静默产出一个"看起来正常、但知识库用不了"的包。

核心产物支持自检：

```powershell
agent-core.exe self-check [--deep]
```

在冻结环境里验证可选依赖（MCP / chromadb / onnxruntime）是否真的可用。
排查"知识库为什么用不了"时先跑它。

### 两级验收查的不是一回事

**`verify:core`** 验「Python 产物本身」—— 重点是三类**必然扫不到**的动态导入，
漏打包不会让构建失败，只会让 exe 启动后"少一半功能"：

| 类型 | 兜底方式 | 漏掉的症状 |
|---|---|---|
| 技能用字符串模块路径加载 | `collect_submodules("my_agent")` | 技能列表空的，模型一个工具都没有 |
| uvicorn 按平台名挑选 loop / protocol / lifespan | `collect_submodules("uvicorn")` | 启动即崩 |
| MCP SDK 运行期选择传输与协议实现 | `collect_all("mcp")` | MCP 连不上 |

**`verify:app`** 验「Electron 壳 + 核心」的**集成** —— `extraResources` 路径是否解析对、
打包模式能否拉起内置核心、数据目录与数据库迁移是否正常、退出后有没有孤儿进程。
核心单独能跑**不代表** Electron 找得到它，而后者的失败表现是"双击图标没反应"。

## 三、发布产物

```powershell
cd desktop
npm run publish:local                     # 构建 → 打包 → 自检 → 产出
npm run publish:local -- --skip-build     # 复用已有产物
```

产出三类东西：

| 产物 | 用途 |
|---|---|
| NSIS 安装包（`Soulmate Agent Setup <版本>.exe`） | 首次安装 |
| `manifest-cn.json` / `manifest-seoul.json` | 两条线路（大陆 / 首尔）的更新清单 |
| `files/<sha 前 2 位>/<sha256>.bin` | 按内容哈希去重的文件池 —— 改哪个文件只下哪个 |

清单与文件池的约定（**别改这个形态**）：

```
<BASE>/manifest-<line>.json
<BASE>/files/<sha 前 2 位>/<sha256>.bin
```

> ⚠️ 发布脚本产出的是**给更新器用的数据**。客户端的检查与下载入口不在本文档范围内
> （当前版本尚未实现端到端自动更新，只具备产物生成能力）。
>
> ⚠️ 上传时**覆盖 manifest、追加 files、绝不删旧 files** —— 老版本客户端可能仍在用旧哈希的文件。

## 四、打包时容易踩的三个坑

1. **`electron-builder` 看不见系统代理**。它用 `got` 下载构建工具包，而 `got` 只认
   `HTTPS_PROXY` 环境变量，**不读 Windows 注册表**。而代理软件通常只写注册表 ——
   于是"我明明开了代理，它还是连不上 GitHub，卡到 600s 超时"。
   `scripts/dist.mjs` 会自动探测注册表代理并补上环境变量，同时为 `127.0.0.1`
   设置 `NO_PROXY`（否则本机请求也会被转发出去）。镜像策略也随之调整：
   **有代理就走官方源**（镜像可能落后于上游版本），无代理才用 npmmirror。

2. **批量删除保护**。单次超过 500 个文件的删除会被系统拦截，而 `electron-builder`
   开始前要清空 `release/win-unpacked`（600+ 文件），PyInstaller 的 COLLECT 也要删旧产物目录
   （500+ 文件）—— 两处都会报出形似"构建失败"的错误。两个脚本都用**先改名再构建**绕开
   （改名不算删除），收尾时再用外部进程清掉挪开的目录。

3. **应用图标**。不配的话打包日志会写 `default Electron icon is used`，装上就是一个默认的
   Electron 图标。图标放在 `desktop/assets/icon.png`，由 `package.json` 的 `win.icon` 指定；
   `electron-builder` 会自动生成多尺寸 `.ico`。

## 五、每次测试前先清零

反复测同一个功能时，上一次留下的配置会一直影响下一次（模型配置、加密密钥、历史会话、
日志、Chromium 缓存），于是「改了没生效」和「改动真没生效」长得一模一样。

```powershell
cd desktop
npm run reset:local                 # 备份后清空 %APPDATA%\Soulmate Agent（含历史旧目录名）
npm run reset:local -- --shortcuts  # 顺带删掉旧快捷方式并刷新图标缓存
npm run reset:local -- --purge      # 直接删除，不留备份
```

默认**先改名成带时间戳的备份再清空**，而不是直接删：那个目录里有真实密钥与历史会话，
留一份备份的成本接近零，误删的代价却是不可逆的。应用正在运行时会拒绝执行
（避免删掉正在写入的 SQLite），确认无所谓可以加 `--force`。

## 六、已知限制

- **未做代码签名**：安装时 Windows SmartScreen 会给出警告，需要代码签名证书才能消除
- **未在独立的干净 Windows 机器上做安装验收**：已用「全新数据目录 + 打包后的完整应用」
  覆盖了等价路径（内置核心能拉起、无需预装 Python/Node、数据目录与数据库迁移正常），
  但安装器在别人机器上的表现（权限、杀软拦截、快捷方式）仍未实测
- 目前**仅支持 Windows**
- `mcp` 是可选依赖，未安装时应用照常运行，「MCP 服务」页会给出安装指引
- MCP 只支持 **stdio** 传输；resources 与 prompts 尚未接入，只用 tools
- 提醒只在应用运行时触发；关闭期间的到点提醒会在下次启动补发
- 产物预览是**只读**的；`.xls` 与扫描版 PDF 不支持预览
- **客户端的端到端自动更新尚未实现**：目前只有发布侧的产物生成
