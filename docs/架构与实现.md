# 架构与实现

> 这份文档记的是**为什么这么做**，而不是"做了什么"。如果你要改这里的某段代码，先看对应章节。

---

## 一、进程模型与安全边界

```
Electron 主进程 ──spawn──> Python 核心（127.0.0.1 随机端口）
      │                          ▲
      │  stdout 握手取端口+令牌    │ 每请求带 X-Local-Token
      └──> React 渲染层 ──────────┘
```

- Python 只监听**回环地址**，令牌每次启动随机生成、**重启即失效**
- 渲染层开启 `contextIsolation`，preload 只暴露白名单 IPC 方法
- **必须绕过系统代理**：Windows 上 Chromium 会使用「Internet 选项」里的代理，导致对
  `127.0.0.1` 的本地请求也被转发而失败。主进程已 `setProxy({ mode: 'direct' })`，
  测试侧用 `trust_env=False`

## 二、权限确认

高危技能（写文件、发请求、执行命令）的执行被拦在 `PermissionGuard`：

1. Agent 循环内 `SkillManager.execute()` 先做权限校验
2. 需要确认时，服务层把 `permission_request` 事件写进**同一条 SSE 流**
3. Agent 循环用 `asyncio.Event` 挂起，等待前端 `POST /v1/confirm` 回传
4. 超时（默认 120s，可配置）**按拒绝处理** —— 宁可少做，不可误做
5. 无确认通道时明确拒绝，且错误信息区分「没有通道」与「用户拒绝」

> 为什么确认请求要走**同一条** SSE 流：另开一条连接时，前端要同时读两条流并保持它们
> 的相对时序，而"边读流边发确认请求"在单连接下才不会有死锁。

## 三、工具调用可视化

后端把 Agent 循环内部状态以事件流形式外发，前端据此渲染工具卡片：

| SSE 事件 | 前端表现 |
|---|---|
| `tool_call` | 插入卡片，状态 = 运行中 |
| `tool_result` | 卡片更新为成功 / 失败 / 被拒绝，并显示耗时 |
| `permission_request` | 弹出确认对话框 |
| `trace` | 右侧「执行链路」抽屉：每个 span 的名称、耗时、token |

## 四、持久化

SQLite 落在 `%APPDATA%\Soulmate Agent\data\agent.db`。四张主表：

| 表 | 内容 |
|---|---|
| `sessions` | 会话元数据（标题、模型、消息数、可用技能子集） |
| `messages` | 消息体，含 `tool_calls`（JSON）与 `tool_call_id` |
| `audit_log` | 每次技能调用的审计记录（参数已脱敏） |
| `files` | 工作区文件元数据（原始名、大小、MIME、类型） |

另有记账与提醒相关的表。

三个关键取舍：

1. **启动只载入元数据，消息懒加载** —— 否则几百个历史会话会拖慢启动
2. **每轮对话结束后整体替换该会话的消息** —— 相比增量 append，能天然处理「重新生成」
   「截断回滚」等场景，不会因某次写入失败导致数据库与内存长期不一致；几百条消息全量重写不到 10ms
3. **数据库不可用时降级为内存模式** —— 应用照常可用，界面会提示"对话不会保留"

## 五、附件与工作区

`POST /v1/files/upload` 接收附件，落在 `workspace/`；技能产生的文件归档到 `artifacts/`。

三条安全底线：

- **存储名由服务端生成**（uuid + 后缀白名单），原始文件名只作展示字段，**绝不参与路径拼接**
- **按 id 解析路径时校验结果仍在根目录内**，`../` 之类的构造会被拒绝
- 屏蔽 `.exe` / `.bat` / `.ps1` / `.dll` 等危险后缀，单文件上限 50 MB

发消息时可带 `attachments: [fileId]`，后端会把**文件绝对路径**注入到用户消息前
（用 `[附件]...[/附件]` 包裹），因为后续的 `excel_read` / `doc_parse` 之类技能接收的都是路径；
前端展示时自动剥掉这一段。

## 六、审计日志

每次技能调用（成功 / 失败 / 被拒绝 / 超时）都会写入 `audit_log`，参数在**写入前**统一脱敏。
「日志」页可查看、筛选与清空，启动时按配置的保留天数自动清理。

另外还有一类**业务操作留痕**（搭子 / 群 / 会话 / 任务的创建、修改、删除、开始、中断）。
两类进**同一张表** —— 用户要按时间顺序看它们（"任务失败前他先删了个会话"这种前后关系，
分两张表就看不出来了）。

## 七、服务端主动推送

提醒到点需要**服务端主动通知客户端**，这与「请求-响应」模型不同，因此另开了一条连接级 SSE：
`GET /v1/events`。

- 后台调度器定期轮询到点提醒，触发后发布 `reminder` 事件
- 前端订阅后弹出应用内通知，并调用系统通知再提醒一次（用户可能已切到别的窗口）
- **提醒通知不自动消失** —— 一闪而过的提醒等于没提醒
- 断线由前端自动重连

MCP 的连接状态也走这条通道（`mcp_status` 事件）。

## 八、搭子（Agent 预设）

搭子把「人设 + 模型 + 可用工具 + 权限策略」打包成一个可切换的整体。

内置 3 个：**Relation Buddy**（人际关系与职场杂事，不限制工具）、**Soulmate**（日常陪伴）、
**Love Buddy**（情感关系）。

提示词就是该搭子自己的**五个人格文档**（`IDENTITY → SOUL → USER → MEMORY → RULES`，
放在 `data/assistants/<id>/` 下，界面上可查看可编辑），**没有额外的兜底提示词**。

三个值得注意的点：

1. **给搭子限定工具是个实用技巧**：模型能选的工具越少，选错的概率越低。
   空列表 = 不限制，不是"什么都不能用"
2. **切换搭子不清空历史**。清库看起来"干净"，代价是毁掉用户正在进行的对话且不可逆；
   技术上也不需要 —— 每轮都会用 `ensure_system()` 就地替换 system 消息，
   永远只有一条 system，不存在"两套人设"共存
3. **技能白名单只填内置技能名**，不要填 MCP 工具名（`server__tool` 随连接状态增删，
   写死了会指向空气）。界面对已失效的白名单项会划线提示

## 九、产物预览

Agent 产出的图表（SVG）、报告（Markdown）、表格（CSV/XLSX）会登记为**产物**，
在右侧抽屉「产物」页签里直接预览；也可以上传文件后预览（Word / PDF / 图片 / JSON 都支持）。

- **不引入 pandas**：CSV 用标准库、XLSX 用 openpyxl 的 `read_only` 流式读取
- **限行限字符**：表格最多 200 行 × 5 个 sheet，文本 12 万字符，PDF 20 页；
  超限如实标注"已截断" —— 用户可能上传几万行的表，预览不能把内存吃满
- **解析失败不报错**：返回 `kind=unsupported` 加可读原因，一个损坏的文件不该让接口 500
- **SVG 与图片走 blob URL 渲染**，不内联 SVG 文本：那等于把上传的文件当 HTML 执行，
  一个带 `<script>` 的 SVG 就能拿到 preload 暴露的 IPC 桥

## 十、MCP 集成

「MCP 服务」页可以图形化增删 MCP Server，它的工具会**自动包装成技能**进入统一工具列表 ——
Agent 循环、工具卡片、权限确认、审计日志全都自动生效，不需要为 MCP 单独写一套。

> 首次体验建议先加**随附的本地示例服务**（`core/examples/sample_mcp_server.py`）：
> 免安装、免联网，加完立刻能看到工具。社区 Server 通过 `npx` / `uvx` 现下载，
> 首次连接需要联网等几十秒。

三个关键设计：

1. **actor 模型**。官方 SDK 的 `stdio_client` 内部用 anyio 的 cancel scope，
   而 cancel scope **必须在创建它的任务里退出**。跨任务 `connect()` / `close()` 会报
   `Attempted to exit cancel scope in a different task` —— 这个错误信息完全看不出根因。
   所以每个 Server 由一个后台任务包办「连接 → 服务命令 → 断开」，外部只通过命令队列交互
2. **命名空间用双下划线**。`server__tool` 而不是 `server_tool`：单下划线无法区分
   「Server `a_b` 的工具 `c`」与「Server `a` 的工具 `b_c`」。超长名会截断并追加哈希，
   保证仍是合法（`^[a-zA-Z0-9_-]{1,64}$`）且唯一的函数名
3. **权限按「注解 → 写动词 → 读动词 → 保守默认」四级推断**。优先采信 MCP 自己声明的
   `readOnlyHint` / `destructiveHint`；判断不出来时归为需确认 —— 第三方 Server 的工具
   我们一无所知，默默放行才是真正危险的选择。注意按**词元**而非子串匹配：
   `prune_cache` 里含有 `run`，子串匹配会把它误判成写操作

**崩溃自愈**：每 30 秒主动探活一次（子进程死掉时命令循环只是静默等待，不会收到通知，
必须主动探活）。发现无响应就重连，连续 3 次失败则停止并提示用户手动处理，
避免"配置写错 → 无限重启"刷屏。

**状态实时同步**：连接状态变化通过 `/v1/events` 推送，界面上的连接灯立刻变；
Server 掉线时它的工具会**立即从模型可见列表里消失**，否则模型会去调用一个不存在的服务。

## 十一、文件访问白名单

`PathPolicy` 是所有文件类技能的强制入口（`ctx.resolve_path()`）：

- **白名单为空 = 不限制**（个人桌面应用的合理默认，界面上会明确提示）
- **工作区与产物目录永远放行**，否则会出现"上传了附件却读不了"
- 按**路径层级**比较而非字符串前缀，避免 `/data/a` 放行 `/data/a-evil`
- 拒绝 `../` 穿越，并给出「去哪个设置项添加目录」的可操作提示

---

## 十二、密钥安全

API Key 与 MCP 的密钥类环境变量**不落盘明文**：

```
Electron 主进程                            Python 核心
  safeStorage（Windows DPAPI）加密
  → secrets.bin
  → 解密后写一次性临时文件  ──路径──→  读取后立即删除
     （AGENT_SECRETS_FILE）            → 仅内存注入，不落盘
  → 渲染层通过受限 IPC 取用             → 保存配置时剥离密钥字段
```

四个设计要点：

1. **密钥归主进程所有**。渲染层要渲染模型输出与上传的文件，是不可信边界；
   Key 一旦被注入的脚本读到就能外传
2. **交接用临时文件而不是环境变量**。环境变量会被子进程继承，而核心会 spawn
   MCP Server，Key 会直接漏给第三方进程；传路径则只有核心知道，且读完即删
3. **落盘剥离、内存保留**。`models.json` 的 `api_key` 恒为空串；MCP 的 env 只剥离
   **名字像密钥**的那些（`key` / `token` / `secret` / `password` / `credential` / `auth`），
   `LOG_LEVEL` 这类普通配置留在 `mcp.json` 里更透明
4. **旧配置自动迁移**。主进程在拉起后端**之前**扫描 `config/*.json`，
   把历史遗留的明文密钥搬进加密存储并抹掉原字段

> 独立运行后端（`python -m my_agent`，没有 Electron）时行为与以前一致：Key 留在配置文件里。
> 因为此时没有 safeStorage 可用，照样剥离会让用户填过的 Key 静默消失。
> 这个区分以「是否传了 `AGENT_SECRETS_FILE`」为准。

系统不支持加密时（`safeStorage.isEncryptionAvailable()` 为 false）会降级为明文并在日志中告警 ——
宁可让用户知道风险，也不要假装安全。

## 十四、工程约定

- **依赖能省就省**：只用 `openpyxl` 不用 pandas；图表用纯 Python 生成 SVG 不用 matplotlib ——
  两者都是打包体积与启动时间的大头，而本项目需要的功能用标准库即可完成
- **核心产物用 onedir 而不是 onefile**：onefile 每次启动都要把几百 MB 解压到临时目录，
  冷启动从 1~2 秒变成十几秒，而且"自我解压"的行为在不少杀软眼里就是可疑动作
- **动态导入必须有兜底**：技能按字符串模块路径加载、uvicorn 按平台名挑选实现、
  MCP SDK 运行期选择传输 —— 这三类漏打包**不会让构建失败**，只会让产物启动后"少一半功能"，
  所以打包配置里有显式的收集与断言（见 `docs/开发与发布.md`）
- **文档与注释写"为什么"**：本项目大量注释解释的是取舍与踩过的坑，改代码前请先读它们
