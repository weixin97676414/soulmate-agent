# Soulmate Agent 1.0.3 更新说明

> 这一版修一个问题、加一个能力、顺手改一处体验。

---

## 一、修：点开工具气泡就卡死、内存爆到 9 GB

**症状**：任务里点「访问网页 / 接口」这类工具的气泡，界面当场卡住，任务管理器里渲染进程冲到 6~7 GB。

**原因**：三个环节叠在一起 ——

1. 工具返回的是**整个响应体全文**（`http_fetch` 拿到 5 MB 的 HTML 也是全文）；
2. 后端序列化成 JSON 时**不换行**（`json.dumps` 默认输出一行），于是变成一条**几 MB 的超长单行**；
3. 前端把这段直接塞进 `<pre>`，而 `whitespace-pre-wrap` 要为它逐字找断行点 ——
   **无换行符的超长单行，布局代价接近平方级**。点开就等于让浏览器去啃几百万字符的一整行。

**修法**（三层，且**不改**"完整读取响应体"的既有口径）：

| 层 | 改动 |
|---|---|
| 后端序列化 | JSON 改为**多行**（`indent=2`），布局恢复线性 |
| 后端展示 | **模型仍拿完整内容**（`memory/spill.py` 无损外置照旧），但**给界面的结果截到 3.2 万字符**，并注明"已省略多少" |
| 前端 | 展开时默认只渲染 4000 字符，「展开全部」才全量；`<pre>` 加 `break-all`，超长单行不再撑爆布局 |

> 为什么不干脆在后端截断？因为「响应体完整读回」是你之前明确定下的口径 ——
> "外部服务是花钱买的，我们没资格替人省略"。所以这次是**分流**：模型拿全，界面拿预览。

## 二、加：Buddy Manager 专属「执行命令行」

新增技能 `buddy_run_command`（**专属技能**：只有 Buddy Manager 能用，其它搭子连看都看不到）。

- 能跑任意命令行（Windows 走 `cmd.exe`，Linux / macOS 走 `sh`），
  返回退出码 / stdout / stderr / 耗时
- **每次都要你点确认**，而且**不能被「记住这个技能」放行** ——
  它能跑任意命令，等于最高权限，不该变成橡皮图章
- 超时会**杀掉整棵进程树**（不会留下 `npm` / `node` 孤儿继续占 CPU）
- 工作目录过文件白名单；命令本身不做黑名单过滤（任何黑名单都能绕过），
  防线就是"你亲自点确认"

---

## 三、改：硅基流动显示所有模型

之前「获取模型」只会留 deepseek 的 flash 档，这家其它厂商的模型一个都看不到，想用只能手打全名。

现在**全量显示，一个都不裁剪**。只多做一件事：把 deepseek flash 族排在最前 ——
因为清单第一项会被自动选成默认模型，排前面是让它落回一个合理默认。

---

## 四、怎么试

1. **试卡死**：找个返回大内容的接口（比如一个网页），让搭子 `http_fetch` 一下，点开工具气泡。
   应该**秒开**、只显示前 4000 字符 + 「展开全部」按钮，不再卡死。
2. **试命令**：让 Buddy Manager「帮我跑一下 git status」。应该弹确认框、框里能看到完整命令；
   允许后返回输出。
3. **试模型列表**：设置 → 模型 → 硅基流动 → 点「获取模型」，应该能看到这家所有模型。

---

## 五、已知限制（如实说明）

- 工具结果的**完整内容仍然只给模型**（界面是预览）。要看全文，让搭子「把结果写到产物文件」。
- 执行命令行**不能用「记住这个技能」批量放行** —— 这是故意的。
- 气泡仍**没有虚拟滚动**：极长会话（几千条消息）开久了内存还是会缓慢上涨。
  这次排掉的是"点一下就爆"的雷，不是全部内存问题。
- 本次核心变了，从 1.0.2 升级需要**重装完整包**，不是增量更新（数据会保留）。
